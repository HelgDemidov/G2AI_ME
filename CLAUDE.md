# G2AI_ME — Claude Code memory

## Принцип ведения памяти проекта

Правило ниже — не про один файл, а про ВСЮ систему фиксации памяти проекта: этот документ (CLAUDE.md, всегда загружен), внешнюю память ассистента (`~/.claude/projects/.../memory/` — MEMORY.md + `project_*`/`feedback_*`/`reference_*`), и внутренние дизайн-доки (`docs/`, где та же дисциплина уже отдельно закреплена для бэклога `pipeline_improvements.md`). Один принцип, применяемый на каждом уровне, а не только здесь.

**Устаревшие/потерявшие актуальность записи ЗАМЕНЯЮТСЯ новыми, а не дополняются ими.** При N-й реализации уже описанного паттерна — консолидировать (одно описание паттерна + что нового в этот раз), не добавлять ещё один похожий абзац рядом со старыми; при структурном фиксе, закрывающем повторяющуюся проблему, — сжать историю прежних инцидентов до итога+фикса, не оставлять её полным текстом рядом с новой записью о фиксе. Объём после правки должен оставаться на месте или сжиматься, не расти монотонно с каждым мерджем/сессией.

**Первый кандидат на сжатие/удаление — упоминания мотивации действий куратора в отрыве от архитектурного факта** («куратор попросил», «решение пользователя», «по прямой просьбе», «куратор спросил, почему...»). Куратор помнит свои мотивации сам; на итоговую реализацию/архитектуру они не влияют — важно только то, что в итоге сделано и как оно работает. Кто/почему инициировал изменение — процедурный retention, не часть архитектурной картины. Исключение — когда мотивация И ЕСТЬ содержание правила (напр. действующая политика конфиденциальности, а не история её принятия): формулировать как правило («X не делается»), не как акт решения («куратор решил не делать X»).

**Нюанс для внешней памяти ассистента:** там же живёт легитимный, отдельно защищённый класс содержания — рационале решений в `feedback_*`/`project_*` (**Why**-строки, история отвергнутых альтернатив), которое НЕ подпадает под «сжать мотивацию» — оно объясняет неочевидные ограничения, полезные при будущих похожих развилках, и тело `feedback_*` untouchable по правилам `/memory-sync`. Различие: «куратор попросил X» (кто/когда — процедурный шум) vs «X отклонён, потому что Y» (архитектурная причина — сохраняется).

## О проекте
Независимый исследовательский трек. Две параллельные, но связанные линии работы:

1. **G2AI-корпус** (`sources/`, `pipeline/scripts/`) — сбор и структурирование международного опыта государств по построению политики/инфраструктуры/регулирования под GenAI и агентные сервисы («государство как MCP-сервер»), в фокусе малые страны, но не исключительно. Конечная цель — пакет предложений от независимого эксперта/отраслевой ассоциации, включая черновик Стратегии ИИ Черногории до 2030, пока правительство её разрабатывает.
2. **Более широкое видение цифрового суверенитета Черногории** (`docs/project_core/vision_and_plan.md`, v03) — параллельный (не строго вложенный в G2AI) трек: ядро локали `cnr`, мобильные клавиатуры, Wikipedia/Wikidata grounding, B2B2G с телеком-группами, дальняя цель — партнёрство государства с фронтир-лабой по «исландскому пути». G2AI-корпус — один из аналитических входов для этого видения, но не единственный и не главный по объёму документа.

Обе линии объединяет забота о точной и полной представленности Черногории в цифровом/ИИ-пространстве.

**`.gitignore` под `/sources/` — deny-by-default:** игнорируется всё (документы `raw.*`/`doc.md`/`.state.yaml`, шарды `candidates/`, `.state/`), КРОМЕ `meta.yaml` — курируемая мета (библиография/аналитика, не тела документов) версионируется в git, а сами документы (потенциально авторское право, см. «Статус» ниже) остаются локально. `docs/` (вся документация: видение, чартеры, спеки, бэклог) — тоже gitignored. `.claude/` — тот же паттерн deny-by-default с негейтом (PR #27): `/.claude/*` игнорируется, КРОМЕ `!/.claude/skills/` — канон Agent Skills трекается, остальное (`commands/` шимы, `settings.local.json`) остаётся локальным.

`.venv/` в КОРНЕ репо — локальный venv через `uv` (в `.gitignore`, не коммитится; venv непереносим — не копировать, а пересоздавать: `uv venv .venv && uv pip install -r requirements-dev.txt`; классический `source .venv/bin/activate` у uv-venv может не работать — вызывать бинарники как `.venv/bin/…`). Конфиг инструментов — `pyproject.toml` (mypy/ruff/pytest; `pythonpath`/`mypy_path` указывают на `pipeline/scripts`, поэтому проверки запускаются ИЗ КОРНЯ, кеши тоже оседают в корне). Проверки перед коммитом изменений в коде пайплайна (из корня): `.venv/bin/ruff check pipeline/scripts && .venv/bin/python -m mypy pipeline/scripts && .venv/bin/python -m pytest -m "not heavy" && .venv/bin/python pipeline/scripts/validate_sources.py` (`validate_sources.py` — 4-й шаг CI с PR #5). ⚠ Бездумный bare `pytest` без фильтра — распространённая локальная ошибка (найдена живьём 2026-07-21): тянет `@pytest.mark.corpus`-голден (`test_convert_golden.py`, реконверсия каждого документа `sources/` байт-в-байт) — ~90-100 c на 6 документах и растёт с корпусом, при этом CI её не видит вовсе. Не баг/паразитный процесс — тест легитимен, просто не «полный гейт по умолчанию». **Маркер `heavy`** (`pipeline/scripts/tests/conftest.py`, PR #41, 2026-07-24) — умбрелла: `pytest_collection_modifyitems`-хук автоматически проставляет его любому тесту, несущему `model`/`corpus`/`ocr`/`libreoffice`/`mermaid`/`browser`. Общий класс — тулинг, физически присутствующий на ЭТОЙ машине (bge-m3/`ocrmypdf`/`soffice`/gitignored mermaidx-фикстуры/Node+`pipeline/browser/lightpanda`), плюс растущий локальный `sources/`: соответствующие тесты НЕ скипаются локально (в отличие от CI/свежего клона, где их не из чего собрать), без фильтра съедают ~2 минуты реального рендера/OCR/реконверсии на прогон «полного гейта», сигнала для CI это не даёт. Раньше фильтр рос строкой имён, продублированной в CLAUDE.md/CI/скиллах — подтверждённый ТРИЖДЫ (PR #26/#37/#40) класс дефекта «забыли добавить новый маркер в одну из копий строки» (см. память `feedback_full_gate_corpus_marker.md`). `heavy` — структурный фикс: новый такой маркер добавляется правкой ТОЛЬКО списка `_HEAVY_MARKERS` в `conftest.py`, команда гейта (`-m "not heavy"`) больше не меняется никогда. Индивидуальный маркер (`-m ocr`/`-m corpus`/`-m browser`/…) по-прежнему гоняется отдельно и осознанно при правках соответствующего слоя — `heavy` его не заменяет, а дополняет. mypy — РЕКУРСИВНО по каталогу (с repo-layout 2026-07-16 проверяются и подпакеты, и тесты; прежний file-glob `pipeline/scripts/*.py` тесты не видел вовсе). **Property-based тестирование (`hypothesis`) — общепроектный стандарт** (не разово, спек `test-coverage-hardening`, 2026-07-21) для геометрического/интервального кода — применён к `detect_columns`/`group_into_lines` (pdf, `test_pdf_to_markdown_properties.py`) и к `render_chart` (`chart-data-extraction`, PR #30 — `test_chart_render.py`/`test_chart_render_visual.py`, второй файл гоняет реальный mermaidx-рендер сгенерированных данных, маркер `mermaid`); прежнее применение к xlsx-функциям `_ownership_ranges`/`_blank_foreign_cells` устарело — обе функции и их hypothesis-тесты удалены вместе с mutual-ownership-системой при переходе на data-driven чарты (PR #30, см. «Слой конвертации»). `reportlab` — dev-зависимость для синтетических PDF-фикстур в тестах (реальные объекты `pdfplumber`, генерируются на лету, не коммитятся). **Unit-тесты герметизированы от боевых артефактов** (PR #25): autouse-guard в `tests/unit/conftest.py` снимает stat до/после каждого теста с corpus.db и боевых КАТАЛОГОВ `sources/candidates/`+`sources/.state/` (каталогом, не перечислением файлов: новый операционный артефакт больше не требует правки списка guard'а) — тест, зовущий `main()`/CLI без явных tmp-путей (`--db`/`--root`), падает громко (живой инцидент 2026-07-21: два main()-теста без `--db` тихо вычищали боевой индекс при каждом прогоне pytest; CI не ловил — без bge-токенизатора стадия индекса пропущена).

## Пайплайн сбора документов
1. **Discovery + триаж релевантности (ДО добычи)** — WebSearch: найти реальный документ/издателя/дату (заголовок из чужого списка/выдачи — не доказательство существования документа: живые кейсы фиктивных заголовков ОАЭ и Эстонии) и оценить релевантность. Кандидат заводится в слой кандидатов `sources/candidates/` (`CandidateRecord`); допущенный триажем промоутится в курируемый `meta.yaml` папки-документа через `schema.promote_candidate()`. НЕ WebFetch для тела документа — прогоняет через маленькую модель, не verbatim; годится только для метаданных. Ядро генератора кандидатов (`discovery-core`) и ручной/directed-каналы (`discovery-manual`) реализованы — см. «Слой знаний» ниже; кандидат заводится ТОЛЬКО через `discover.py inject` (единственная дверь: dedup+провенанс by construction; новая РЕДАКЦИЯ документа входит той же дверью с `--supersedes <doc-id>`), триаж — батч-сессией `discover.py worksheet` → decisions.yaml → `discover.py apply`; протокол поисковых кампаний — скилл `.claude/skills/directed-search/{SKILL.md,README.md}` (Agent Skill, трекается — PR #27). **Строгость Стадии 1 канально-дифференцирована** (политика, не код — спек `triage-channel-policy`): `manual`-канал с документом, который куратор лично читал, — без WebSearch, Стадии 1/2 сливаются в одно касание (`promote` сразу с `assessed_stage: confirmed`); `directed_search`/`registry` (батч-каналы) — WebSearch обязателен, кандидаты из поисковой выдачи/чужих дампов наследуют её ненадёжность.
2. **Скачивание оригинала** — через `run_pipeline.py`: acquisition-лестница `direct → official_alt → (browser, только expected=html) → manual → archive` при WAF-блоке/мёртвом URL (см. «Слой знаний»), в `sources/{track}/{entity}/{doc-id}/raw.*` (расширение — `SourceFormat` записи: pdf/html/docx/xlsx); sha256/канал добычи → `.state.yaml`.
3. **Конвертация** — `converters.resolve_converter(raw)` диспетчеризует по расширению (`SourceFormat`: pdf/html/docx/xlsx) → `doc.md`; frontmatter порождается из `meta.yaml` (`schema.render_frontmatter`), не пишется вручную. Подробности — раздел «Слой конвертации» ниже.
4. **Подтверждение** — Стадия 2: по тексту `doc.md` подтвердить/понизить `relevance.target_fit`; `validate_sources.py` требует `relevance` у каждой записи корпуса (гейт в CI и в `run_pipeline`). **Для батч-каналов (`directed_search`/`registry`) Стадия 2 ленивая** (`triage-channel-policy`): допущенный кандидат штатно живёт с `assessed_stage: triage` неограниченно долго (это НЕ долг), подтверждение — при первом аналитическом использовании документа (evidence-пак/матрица/чтение), не сразу после конвертации; обнаруженный мусор/нерелевантность → немедленный даунгрейд/`rejected`.

5. **Жизнь после приёма** — `run_pipeline.py --recheck` (контур времени, PR #48): периодическая команда куратора, проверяющая условными запросами, жив ли официальный URL и не подменил ли издатель файл; findings (`drift`/`link-rot`/`resurrected`) флагуются в `.state.yaml`, решение — за человеком. Подробности — буллет «Контур времени» в «Слое знаний».

## Слой знаний: метаданные, граф, семантический поиск
Поверх собранных `.md` — слой для кросс-документного анализа (Фазы 1-4 реализованы, влиты в `main` через PR #1; проектный план и статус — `docs/pipeline/knowledge/tech_specs/knowledge-graph-metadata/spec.md`, gitignored). Всё CPU-only, встроенное, без серверов/JVM/CUDA. Скрипты запускаются ИЗ КОРНЯ: `.venv/bin/python pipeline/scripts/<script>.py`.

- **Метаданные** — `schema.py` (слим по corpus-layout-v2, PR #4): курируемое ядро `SourceRecord` (~21 поле) в `meta.yaml` — id, `entity_id`/`track`, issuer_type, geo_scope, language (ISO 639-1, либо 639-3 там, где 639-1 нет — черногорский `cnr`; PR #5), dates, doc_type, authority, source_url, sensitivity, rights, topics, g2ai_pattern, summary, relations, relevance (Dublin Core + минимум аналитики). Операционное (sha256/acquisition/…) — отдельная модель `OperationalState` в `.state.yaml`-sidecar (машина пишет `save_state` через `fsio.atomic_write_text`, НЕ в `meta.yaml`; comment-safe); `raw_size`/`raw_mtime_ns` — stat-guard, чтобы не перечитывать raw целиком на каждом прогоне (PR #7). **Ручная бухгалтерия свежести из курируемого ядра УДАЛЕНА** (`in_force`, `dates.last_checked`; `post-acquisition-lifecycle`, PR #48): ручной bool «действует ли закон» и ручная дата «когда проверяли» на сотнях записей протухают по построению и не имели ни одного кодового читателя — их работу выполняют машиннописаный `acquisition_checked` (курсор recheck-контура) и ВЫВЕДЕННАЯ валидность из рёбер `supersedes`/`superseded_by` (общий хелпер `schema.superseded_ids()` — одно определение на recheck-ротацию и будущий фасет graph-v2, нормализует оба направления ребра). ⚠ `meta.yaml` — единственное, что в `sources/` трекается, поэтому такие слимы требуют миграции ДАННЫХ тем же коммитом: `extra="forbid"` иначе роняет `validate_sources` на свежем клоне (для полей `.state.yaml`/`OperationalState` — тот же `extra="forbid"`, но файл локальный/gitignored: миграция — одноразовый скрипт, который куратор запускает на СВОЁМ корпусе, не коммитится; живой пример — снятие мёртвого `translation_status`, `acquire-convert-seam-hardening`, PR #53). `external_disclosure_allowed(sensitivity)` — единый предикат политики «confidential не раскрывается третьим сторонам» (PR #53), заменивший 8 разрозненных сравнений с `Sensitivity.confidential` в 7 модулях acquire/convert/discovery/index; AST-based guard-тест не даёт им расползтись снова — новая точка внешнего раскрытия обязана пройти через предикат, иначе тест красный. Инварианты раскладки (папка==id, entity_id, track; глоб. уникальность id) — единая `schema.check_layout()` (PR #8), используется и `load_records()` (raise), и `validate_sources.py` (collect); пути raw/doc.md/state ВЫВОДЯТСЯ из папки (`raw_file`/`md_file`/`state_file`). `render_frontmatter()` порождает frontmatter. `validate_sources.py` — валидатор (структура + словари + уникальность id + relations + `relevance` + инварианты папок + для `geo_scope=national` форма `entity_id` == iso2, PR #5), возвращает `(errors, records)` — потребители (`run_pipeline`/`build_graph`) переиспользуют записи без повторного обхода дерева (PR #8); ненулевой код при ошибках, гейт также в CI (PR #5).
- **Словари** — `pipeline/vocab/vocab_*.yaml` (растут органически); `g2ai_pattern` = переносимый паттерн-решение (ось кросс-странового сравнения), `topics` = тема. `jurisdictions.yaml` (EU/ASEAN) даёт рёбра `member_of`. `axes` (`vocab_axes.yaml`, PR #26, `vocab-axes`) — аналитические оси триажа (`agentic_g2ai`/`digital_sovereignty`), растёт РЕДКО (в отличие от органических topics/g2ai_pattern — новая ось = пересмотр методологии): `Relevance.axis` вынесен из захардкоженного enum `Axis` (`schema.py`) в этот словарь, гейт — `validate_sources.py`, консистентно с doc_type/authority/topics/g2ai_pattern. Правило проекта: enum — если код ветвится по значению ИЛИ это упорядоченная шкала (`TargetFit`/`AssessedStage`/…); словарь — если номинальная содержательная классификация.
- **Граф** — `build_graph.py`: гетерогенный NetworkX-граф (узлы document/pattern/topic/issuer/jurisdiction; рёбра exemplifies/about/published_by/applies_to/member_of + document→document из relations). Экспорт GraphML. Запросы: `docs_by_pattern`, `docs_in_bloc`, `lineage`. **Граф — производная проекция: полная пересборка каждый прогон, автослой НИКОГДА не пишет в курируемое ядро и отличим от него по построению** (`layer` на КАЖДОМ ребре: `L0` курируемое / `L1` детерминированный автослой / `L2` зарезервирован под будущую LLM-экстракцию — значение введено сразу трёхзначным, чтобы она не потребовала миграции атрибутов).
- **Временнáя валидность (graph-v2 Фаза A, PR #49)** — ВЫВОДИТСЯ из рёбер, не ведётся полями: `validity_intervals()` — чистая функция от реестра (`valid_from = dates.effective ?? published`; `supersedes`/`superseded_by` нормализуются к одному направлению и закрывают интервал предшественника датой начала преемника; `amends` НЕ закрывает — поправка меняет, а не заменяет; несколько преемников → самый ранний + WARNING по числу ПРЕЕМНИКОВ, не датированных дат; преемник раньше предшественника → WARNING о пустом интервале, PR #50 — иначе документ исчезал бы из ВСЕХ срезов молча, единственное место, где слой нарушал собственное обещание). Тот же аргумент, что похоронил `in_force`: ручная бухгалтерия на сотнях записей протухает, пересборка бесплатна. **Честная неопределённость**: `validity_known=False`, когда своей даты нет ЛИБО преемник есть, но датировать закрытие нечем — `as_of(graph, date)` такие документы включает ВСЕГДА с пометкой (молчаливое удаление из среза, за который пишутся нормативные предложения, недопустимо). Границы среза: `valid_from` включительно, `valid_to` исключительно — иначе в день стыка редакций действуют обе. CLI `build_graph.py --as-of YYYY-MM-DD` (с `--graphml` экспортирует СРЕЗ, не полный граф). Даты в GraphML — ISO-строкой, `""` для неизвестной (writer падает на `None`).
- **L1: детерминированный слой цитирования** (`graph/cite_mining.py`, PR #49, укреплён PR #50, PR #51) — юридический корпус аномально хорошо цитируем ФОРМАЛЬНО, и это домен-преимущество, которого generic-GraphRAG не видит: рёбра `cites` строятся с НУЛЁМ LLM. **Обе стадии двухканальны — машинная + курируемая.** ЭКСТРАКЦИЯ: реестр регексов по образцу `_CONVERTERS` (`celex`/`eu_act`/`eu_act_slash`/`sluzbeni_list_cg`/`iso`/`nist`/`eli_uri` — новый идентификатор добавляется ЗАПИСЬЮ, не правкой ядра; `IDENTIFIER_PREFIXES` — единственное определение пространства префиксов, PR #51) + секция `aliases` справочника (строка текста → канонический id; literal + границы слов, регистронезависимо, БЕЗ регекс-обобщений). Алиасы существуют потому, что документ законно цитирует акт ИМЕНЕМ без номера: 6 упоминаний «EU AI Act» в `oxford-insights-gairi-2025` дали ПЕРВОЕ реальное ребро L1 в корпусе. ⚠ precision алиасов — на кураторе: голый «AI Act» в том же тексте означает ещё корейский/тайваньский/австралийский/американский акты (4 ложных ребра), берётся различающая форма; неограниченный рост списка (мультиязычные титулы) — триггер L2, не повод обобщать матчинг. РЕЗОЛЮЦИЯ id → doc-id: авто из `source_url` + секция `identifiers` (курируемое побеждает эвристику; протухшая запись → warning + отчёт, НЕ краш). URL-канал намеренно ШИРЕ прозаического: якорь `CELEX:`/`CELEX%3A` читает id verbatim (любой сектор/литеры/длина, хвосты `-YYYYMMDD` консолидации и `R(NN)` corrigendum) — префикс снимает неоднозначность формы полностью, поэтому будущие eurlex-допуски резолвятся САМИ, без строки в справочнике. Симметрично — якорь `\bdata.europa.eu/eli/`/`eur-lex.europa.eu/eli/` (ELI, официальный URI-шаблон законодательства ЕС, PR #52): отображение `eli/{reg|dir|dec}/{год}/{номер}` на сектор-3 CELEX детерминировано, хост — ОБЯЗАТЕЛЬНАЯ часть якоря (национальные ELI-порталы вроде `eli.gov.pl` используют ту же path-грамматику для национального права — без хоста запись строила бы ложные CELEX). Прозаические регексы держат границу v1 (сектор 3 + LRDE + 4 цифры) — расширять их запрещено: ложное ребро дороже пропущенного. Нерезолвнутое не выдумывается — уходит в `sources/.state/cite_leads.yaml` как СЫРЬЁ для discovery (дверь в слой кандидатов остаётся `inject`). Без кэша/сайдкара: детерминировано и дёшево (246 мс на 1.1 МБ). ⚠ **Паттерны калибруются по ЖИВОМУ тексту, не по спеку** — первый прогон дал 0 цитат при 242 живых ссылках (компактного CELEX в конвертированном тексте нет ВООБЩЕ): порядок чисел зависит от эпохи (с 2015 `ГОД/номер`, до того `No номер/ГОД`), год бывает двузначным, и обе ловушки дают не пустой результат, а НЕВЕРНУЮ связь. Год-гейт `1950–2049` отбрасывает совпадение целиком, если на месте года стоит номер (превентивен: на сегодняшнем корпусе ноль срабатываний). Precision сторожит голден `tests/fixtures/cite_golden.yaml` (128 id фиксированной ПАРЫ документов, pattern-only, маркер `corpus`→`heavy`; эталон трекается — идентификаторы это библиография класса `meta.yaml`, не тела): пара фиксирована намеренно — голден по всему корпусу переписывался бы при каждом новом документе, и куратор перестал бы читать диффы.
- **Примитивы экспансии** (`graph/expand.py`, PR #49, уточнён PR #50) — контракт с будущим `analyze-evidence`: `expand(doc_ids, hops)` — точное типизированное соседство ТОЛЬКО по рёбрам документ→документ (через концепт-узлы не ходит: у каждого документа есть тема и издатель, соседство «через topic» вырождается в полкорпуса); `personalized_rank()` — PPR по всему графу, где концепт-узлы работают связующей тканью. `Neighbor.links` несёт ВСЕ параллельные рёбра пары (пара законно связана и `supersedes` из L0, и `cites` из L1 — одна причина из двух делала бы досье тихо неполным); `etypes` гейтит ОБХОД, а не только выдачу («путь целиком из рёбер этих типов»). ⚠ PPR — СВОЯ степенная итерация, а не `nx.pagerank`: тот в networkx 3.x требует **scipy**, которого в проекте нет, а приватный `_pagerank_python` — тот же класс риска, что версийный скос `markitdown`. Замер (1000 док): 201 мс при `PPR_TOL=1e-4`; порог калиброван — 1e-9 давал 458 мс при ИДЕНТИЧНОМ top-20 (нужен порядок соседей, не точные веса).
- **Поиск** — единый `pipeline/index/corpus.db` (SQLite): `corpus_index.py` (канонические ~512-токенные чанки + FTS5 `unicode61`; `build`/`search`), `vector_store.py` (векторы + брутфорс-косинус; `embed-corpus`/`vsearch`/`models`/`drop-model` — последние два, PR #51, гигиена брошенных A/B-неймспейсов: `gc_vectors` чистит только осиротевшие векторы СВОЕЙ модели, `models` даёт обзор всех неймспейсов в БД, `drop-model <имя>` удаляет неймспейс целиком). Чанки канонические — общие для FTS и векторов. **Инкрементальность двухуровневая (PR #9):** документ — единица переиндексации FTS (`doc_state(doc_id, fingerprint)`: пере-чанкуются и пере-индексируются в FTS через external-content `'delete'`/`'insert'` ТОЛЬКО документы с изменившимся `doc.md`; `--force`/смена `chunk_max_tokens` → эталонный полный rebuild; инкремент — одна транзакция, `doc_state` не обгоняет chunks); чанк — единица эмбеддинга, ключ **`content_hash`** (sha256 `breadcrumb + text`, не эфемерный `chunk_id`; breadcrumb — с PR #15, см. ниже): эмбеддятся только новые хэши + `gc_vectors` осиротевших, общий boilerplate-чанк = один вектор на всех носителей. Класс дефекта «вектор указывает на чужой текст» устранён ПО ПОСТРОЕНИЮ → стоп-гэп `DROP vectors`/`vectors_fingerprint`/`VectorsStaleError` (PR #7) упразднён, заменён честным missing-репортом vsearch. `index_meta` (key-value) хранит `corpus_fingerprint` (stat-based глобальный гейт «есть ли работа», реконсиляция пересборки; meta-aware с PR #15 — см. ниже), `chunk_max_tokens`, `schema_version` (v3 с PR #15; открытие легаси-БД пересоздаёт производные таблицы). `corpus_index.py search` по умолчанию экранирует запрос (`sanitize_fts_query` — дефис не входит в bareword-грамматику FTS5), `--raw` — для честного FTS5-синтаксиса. **Потолок брутфорса (замеры 2026-07-21, коммит `e2c3976`):** `load_vectors` собирает ВСЮ матрицу модели на каждый поиск — потоково в предвыделенный буфер (пик ~1x от размера матрицы; прежняя форма `fetchall`+`vstack`+избыточный `astype` давала 3.07x). На целевых ~163 тыс. чанков (1000 док) это ~640 МиБ и ~2.8 c на запрос: по памяти на 8 ГБ проходит, ограничение — латентность. Порог пересмотра (кэш матрицы на сессию → ANN/квантизация) — ~100 тыс. чанков ИЛИ когда задержка начнёт мешать; смена float32→float16/int8 НЕ требует переэмбеддинга (локальная конверсия BLOB'ов), поэтому делать её заранее не нужно.
- **Retrieval-фасад (PR #15, `analyze-retrieval`)** — `chunk_text()` секционирует текст по markdown-заголовкам ДО packing: у каждого чанка `breadcrumb` (цепочка заголовков-предков, `"H1 › H2"`), чанк никогда не пересекает границу секции; `embed_input(breadcrumb, text)` — что реально видит эмбеддер (не голый текст чанка). Схема v3: двухколоночный FTS (`text`, `breadcrumb`) + новые таблицы `doc_facets`/`topics_map` (наполняются из курируемых записей, полная перезапись каждый прогон индексации, дешевле diff-логики); `corpus_fingerprint` — meta-aware (стат `doc.md`/`meta.yaml`), с PR #52 ещё и STATE-aware (+ стат `.state.yaml`) — правка тира/топиков в `meta.yaml` ИЛИ находка recheck/lint в `.state.yaml` без изменения текста триггерит обновление фасетов, но НЕ пере-чанковку/пере-эмбеддинг документа. **Провенанс шва convert↔knowledge** (`convert-knowledge-seam-hardening`, PR #52, аддитивные колонки без бампа `SCHEMA_VERSION`): `chunks.reconstruction`/`chunks.markup_heavy` — чанк несёт машинную VLM-реконструкцию фигуры (границы читаются из терминированного блока инъекции `core/markers.py`, а не восстанавливаются по сайдкару) либо преимущественно разметку (таблица/фенс/маркер); `doc_facets.fidelity`/`ocr_model`/`quality_flags` — сигналы acquire/convert (`fidelity` добычи, модель облачного OCR, ИМЕНА lint/recheck-дефектов из `.state.yaml`), до этого PR не читавшиеся НИ ОДНИМ потребителем index/analyze/graph. Всё — АННОТАЦИЯ в `ScoredChunk`/выдаче `hsearch` (`⚠ reconstruction`/`⚑ <flag>`), фильтров нет — выдача не меняется ни на бит; политика доверия к реконструкции — решение будущего `analyze-evidence`. Единая точка retrieval — `analyze/retrieve.py::retrieve()`: RRF-слияние (`RRF_K=60`/`POOL=50` — константы, не конфиг) FTS5+вектор с фасетными фильтрами (entity/topic/doc_type/authority/axis/target_fit → `doc_facets`/`topics_map`); `embedder=None` — честная FTS-only деградация (для CI/свежей БД без векторов). **Фасет `superseded`** (graph-v2 §2, PR #49) — аддитивная колонка `doc_facets` БЕЗ бампа `SCHEMA_VERSION` (тот дропнул бы `vectors`; на втором применении миграция обобщена в `_ensure_facet_column`/`_ensure_facet_columns` — третья колонка добавляется строкой, не копией функции), множество считает общий `schema.superseded_ids`. `RetrievalFilters.include_superseded` = False по умолчанию: устаревшая редакция закона в top-k evidence-пака — тихая содержательная ошибка класса «вектор указывает на чужой текст». Два неочевидных места, оба закрыты тестами-регрессиями: `retrieve(filters=None)` НОРМАЛИЗУЕТСЯ к `RetrievalFilters()` (самый частый путь вызова — «поле с дефолтом в dataclass» на нём не сработало бы, и исключение молча не применялось бы там, где ошибка тише всего); гейт выражен ВЫЧИТАНИЕМ множества, а не условием в SQL фасетов — иначе `allowed=None` («весь корпус») превратился бы в конкретное множество из `doc_facets` и обнулил бы выдачу на БД с ненаполненными фасетами. Побочно это даёт главное свойство: пока рёбер `supersedes` нет — полный no-op, выдача не меняется ни на бит, включение произойдёт само, данными. CLI `hsearch.py` — тонкий фасад над `retrieve()` (`--backend bge|openrouter|none`, `--include-superseded` для истории, `--sources` — PR #51, advisory-сверка `corpus_fingerprint`: предупреждает в stderr, если индекс собран до последней правки корпуса, не блокирует поиск). Гейт публичен как `analyze.retrieve.apply_superseded_gate` (PR #51, была `_apply_superseded_gate`) — `ab_eval.py` считает его РАЗ на прогон и применяет к ВСЕМ трём режимам (`fts`/`vector`/`hybrid`), не только к `hybrid` через `retrieve()`: иначе с первым реальным ребром `supersedes` режимы начали бы сравнивать разные вселенные документов, и A/B тихо перестал бы быть сравнением одного и того же. `ab_eval.py` — режимы `--mode fts|vector|hybrid|all`; контрольные запросы вынесены в трекаемый `pipeline/config/eval_queries.yaml` (не в коде). **Эмпирическая находка (не дефект):** FTS-режим даёт ~0% hit@k на запросах-перефразировках (implicit-AND по всем токенам полного предложения почти никогда не матчится в естественной прозе) — ровно причина существования гибрида; кросс-язычный EN→cnr retrieval через векторный канал подтверждён рабочим на реальном документе (`me-crps-registration-law-2025`).

- **Оркестратор** — `run_pipeline.py`: идемпотентный end-to-end по корню `sources/` (download→convert→frontmatter→index). Реконсиляция desired-state (работа выводится из ФС: наличие `raw.*` + sha256 из `.state.yaml`, свежесть `doc.md`, синхронность frontmatter) — повторный прогон no-op, самовосстановление; пересборка индекса реконсилируется тем же принципом — по `corpus_fingerprint` (глобальный гейт, не in-run флаг, PR #7), а сама переиндексация инкрементальна по `doc_state`/`content_hash` (PR #9): меняется только изменившийся документ, эмбеддятся только новые хэши. `--embed` реконсилирует векторы при пересборке FTS (бэкенд — `--embed-backend {openrouter,bge}`, дефолт облачный; отказ облака после ретраев НЕ рвёт FTS-часть — она закоммичена раньше, ошибка репортится с ненулевым exit); standalone-добор при актуальном FTS — `vector_store.py embed-corpus`; сводка прогона печатает счётчик чанков без векторов production-неймспейса с подсказкой добора (PR #25 — дефолтный прогон сознательно не эмбеддит, но об отставании векторного слоя больше не молчит); симметрично, с PR #28 сводка считает сканы на локальном OCR-пути (различает отказ облака — WARNING — и намеренно-confidential — INFO), безусловно, включая `--dry-run` (читает только `.state.yaml`, не индекс/сеть). Атомарная запись артефактов документа — через `fsio.py` (единая staging-политика, dot-префиксные файлы вне глобов `raw.*`, PR #6/#8); `fsio.exclusive_flock` (PR #53) — эксклюзивный `flock` на `sources/.state/run_pipeline.lock`, взаимоисключает mutating-режимы (штатный прогон стадий и `--recheck` — оба писатели `.state.yaml`; конкурентный запуск получает `AlreadyLocked`/exit 1, не молчаливую потерю полей при интерливании load→save; `--dry-run` лока не берёт, обязан быть no-op). `needed_stages` проверяет инвариант «расширение `raw.*` == курируемый `source_format`» (PR #53) — рассинхрон (напр. после ручной замены файла при прерванном флоу смены формата) даёт громкий per-документный отказ (изоляция — забота `process_docs`), не молчаливую конвертацию «по файлу». Backoff симметричен для ОБЕИХ стадий, download и convert (`convert_failed`-трио в `.state.yaml`, `convert_deferred`, PR #53) — тот же `RETRY_BACKOFF_DAYS`; патологический документ (напр. многочасовой OCR-таймаут) не повторяет полную стоимость каждый прогон, сводка несёт отдельный класс «конвертация отложена: N». Отказ документа не рвёт батч (включая стадию планирования, PR #6); quality-gate (валидация реестра), `--dry-run`/`--force`/`--only`/`--no-download`/`--embed`/`--watch-dir`; `--recheck` — отдельный режим ВМЕСТО стадий (контур времени, см. буллет ниже; оркестратор грузит/сохраняет там слой кандидатов сам — сшивание слоёв его роль, ACQUIRE о раскладке store слоя DISCOVERY не знает). - **Добыча / WAF-устойчивость** — `acquisition.py` (спек `docs/pipeline/acquire/tech_specs/source-acquisition-ladder/spec.md`, PR #2): лестница `direct → official_alt → browser → manual → archive` на стадии download (`browser` — только `expected=html`, см. ниже). **Детекция блока — двухканальная и растёт по одному правилу** (три живых вендора: Cloudflare PR #2, F5/Akamai PR #42, AWS WAF PR #48): сигнатуры ТЕЛА (`CHALLENGE_BODY_MARKERS`) плюс отпечатки ЗАГЛОВКОВ (`_has_waf_header_fingerprint`: `cf-ray`/`__cf_bm`, `x-amzn-waf-action` со значением challenge/captcha). Ни HTTP-кода, ни размерного порога не достаточно: 42 936-байтная F5-заглушка прошла бы как валидный HTML, а челлендж AWS вообще приходит `202 Accepted` с ПУСТЫМ телом — маркеры тела там не могут сработать в принципе. Обратное правило столь же жёсткое: детектором служит ЗНАЧЕНИЕ (`Server: BigIP` сам по себе ложноположителен на реальном контенте нескольких гос-сайтов), а не факт наличия заголовка. Иначе `200`-challenge сохранился бы как «документ»; сетевые отказы curl (DNS/connect, exit 6/7) классифицируются как `dead` и уходят в archive-ступень, а не роняют документ (PR #6). Ошибка ДИАГНОЗА (исход верен, причина нет) перестала быть косметикой с PR #48: строка причины теперь оседает в `.state.yaml` и читается куратором как вердикт. `manual` — 1-клик путь (`xdg-open` официального URL + watch-folder поверх системной папки загрузок, `xdg-user-dir DOWNLOAD`), синхронен только при `--only` (батч на нём не виснет, просто репортит и идёт дальше); кандидаты сверяются с title документа (грубый порог по словам, с мемоизацией парсинга) — посторонний PDF в папке загрузок больше не может тихо стать оригиналом; явный `--watch-dir` отключает сверку (PR #6). `archive` — снимок из Wayback CDX API для подтверждённо мёртвых URL (`fidelity: archived_snapshot`, никогда не `live`; `sensitivity: confidential` отключает archive — Wayback публикует обращение; запрос берёт РЕАЛЬНО свежайший снимок через `limit=-N`, не первые N по возрастанию, PR #6). Состояние добычи (`acquisition_method`/`fidelity`/`acquisition_checked`/`retrieved_snapshot_date` + sha256) пишется в `.state.yaml`-sidecar документа (`schema.save_state`, plain YAML — файл машиннописаный, без комментариев; `ruamel`/round-trip и `persist_acquisition_state` убраны как ненужные после разделения курируемого/операционного — corpus-layout-v2, PR #4). **Успешная добыча дополнительно закрывает контур времени** (PR #48, см. отдельный буллет ниже): бутстрапит серверные валидаторы `etag`/`http_last_modified` ИЗ УЖЕ РАЗОБРАННЫХ заголовков (ноль новых запросов) под гейтом ступени `VALIDATOR_CAPTURE_RUNGS = {direct, official_alt}` — archive отдаёт заголовки Wayback, browser синтезирует свои, manual вовсе без HTTP-ответа, и записанные как валидаторы документа они давали бы мусорный drift на каждой ротации; просит Wayback SavePageNow сохранить нашу редакцию (`fidelity = live` — ревью PR #53/В8 исключило `rendered` из `_SNAPSHOT_FIDELITIES`: браузерная ступень достигается ТОЛЬКО когда WAF отбил datacenter-IP curl, датацентровый краулер Wayback почти наверняка получил бы тот же челлендж — страховка объявляется неприменимой для этого класса, а не имитируется ложной пометкой; не-confidential, идемпотентно по `snapshot_requested`, fire-and-forget); снимает backoff и гасит `recheck_finding`. Симметрично, ЛЮБОЙ провал лестницы фиксируется одним общим перехватом в `acquisition_failed`/`acquisition_failure_reason` (перечислять типы поимённо значило бы забыть следующий — `ManualAcquisitionTimeout` до PR #48 пролетал бесследно), `needed_stages` не планирует download `RETRY_BACKOFF_DAYS = 7` дней (пробивают только `--force` и `--only <id>` — явное намерение куратора), а сводка выделяет класс «ждут добычи: N», не ошибку. **Ступень `browser`** (`headless-browser-resolver`, PR #40) — между `official_alt` и `manual`, ТОЛЬКО для `expected=html`: одна автоматическая попытка через `core/browser_resolver.py` (Puppeteer-core драйвит Lightpanda по CDP) перед падением в `manual` — закрывает реальный пробел, т.к. watch-folder был и остаётся PDF-only. Инструментарий — `pipeline/browser/` (манифест трекается, бинарь/`node_modules` gitignored, качаются как модели); `Fidelity.rendered` отличает JS-рендер от сырых байтов сервера. PDF/DOCX/XLSX и `dead`-исход резолвер не трогает вообще (не тестировалось за пределами HTML). **Формат-ось добычи — реестром, не if/elif** (`acquisition._FORMAT_PROFILES`, PR #53, зеркало `convert._CONVERTERS`): одна запись на `SourceFormat` (classify-функция/CDX-mimetype/watch-folder-флаг/browser-ступень-флаг) — новый формат добавляется записью, не правками россыпью по модулю; behavior-preserving рефакторинг (все прежние тесты классификации прошли без правок).

- **Контур времени (recheck)** — `acquire/recheck.py` (спек `post-acquisition-lifecycle`, PR #48, 2026-07-26): до него корпус был ФОТОГРАФИЕЙ — документ проходил границу приёма один раз, и никто не проверял, жив ли URL и не подменил ли издатель файл по тому же адресу. Отдельный, взаимоисключимый со стадиями режим `run_pipeline.py --recheck [--recheck-limit N] [--recheck-deep]` — команда куратора, не демон/cron («always-on запрещён» в силе). **Инвариант, зеркальный knowledge-инварианту «проекция не пишет в ядро»: автоматика контура НИКОГДА не мутирует ни `meta.yaml`, ни `raw.*`** — только операционные артефакты; содержательные решения закрывает человек существующими дверями (`inject --supersedes` для новой редакции / `--force --only` для правки на месте). Механика — **условный GET, никогда HEAD**: блок распознаётся только по телу, а HEAD тела не возвращает — `200`-challenge был бы неотличим от контента, и бутстрап из HEAD записал бы ETag challenge-страницы как валидатор документа. Классификатор `classify_recheck()` — чистая функция «состояние+ответ → желаемое состояние»: 304/совпадение → инкремент `etag_confirms`; смена валидатора → `drift` (для `source_format=html` только при `etag_confirms >= HTML_STABLE_CONFIRMS=2` — валидаторы гос-порталов волатильны, без порога первый прогон дал бы шторм ложных срабатываний); 404/exit 6,7 → `link-rot`; WAF → «unverifiable», НЕ finding (блок — состояние канала, не событие документа); `fidelity=archived_snapshot` инвертирует семантику (мёртв → ожидаемо, ожил → `resurrected`). Чистый исход НИКОГДА не гасит стоящий finding — снимает его только передобыча. Курсор `acquisition_checked` бампается при ЛЮБОМ исходе, иначе документ с непогашенным finding вечно висел бы первым в ротации и на каждом прогоне стрелял бы в SPN. Три популяции: (a) записи с raw (суперсидированные исключены через `superseded_ids`; `confidential` НЕ исключается — третьих сторон в условном запросе нет, в отличие от SPN), (b) недобытые — «а не открылось ли?», успех только СНИМАЕТ backoff (добирает штатный прогон — одна дверь к добыче, не две), (c) кандидаты `rejected_kind: unacquirable` с ФОРМАТ-АГНОСТИЧНОЙ классификацией (`classify_probe` — у кандидата `source_format` ещё нет; с наивным `expected=pdf` любой оживший HTML-источник навсегда остался бы «not a valid PDF»). Живая приёмка подтвердила разнородность издателей: часть отдаёт только `Last-Modified`, часть `ETag`, часть (UNDP) не эмитит валидаторов вовсе — на последних работает защитная ветка «сравнивать не с чем», а не ложный drift.

CLI `discover.py discover [--only id ...] [--dry-run]`. **Store** — шард на `connector_id`: `save` партиционирует ВЕСЬ список и пишет только изменившиеся байты (мутация чужого шарда корректна автоматически, dirty-tracking не нужен), опустевший шард удаляется; авто-миграция монолита реконсиляцией с правилом прецедентности (пока монолит жив — он единственный источник истины, удаляется последним шагом: иначе краш посреди записи шардов удвоил бы записи). **Dedup** — кросс-коннекторный, без fuzzy-библиотек (детерминизм важнее recall): три dict-индекса за ОДИН проход (O(M+N) вместо O(M×N)) со строгим приоритетом СТРАТЕГИЙ `normalized_url` → `issuer`+`normalized_title`+`doc_date` → `content_hash` над ЕДИНЫМ пулом; отклонённые триажем не ре-инжектятся. **Идентичность кандидата — ПАРА (URL-идентичность, заявленная редакция):** `CandidateRecord.supersedes` входит во все три ключа И в `raw_hash`; `inject --supersedes <doc-id>` — дверь для новой редакции на ТОМ ЖЕ URL (задокументированная «движущаяся цель» законов), `promote_candidate` материализует ребро `supersedes` (потребитель — вывод валидности `graph-v2`), `pending_candidates` реконсилирует по паре (иначе редакция гасилась бы совпадением URL с предшественником и не попала бы в worksheet). **Ручной/directed-каналы реализованы** (`discovery-manual`, PR #25): `inject` (типизированный завод кандидата через dedup — повторный inject той же ссылки no-op, отклонённые не воскресают), `worksheet` (таблица ждущих РЕКОНСИЛЯЦИЕЙ против реестра, без хранимого статуса; шапка = самодостаточный формат решений), `apply` (батч promote/reject по `raw_hash`-ключу, изоляция отказов per-решение, `--dry-run`; после не-dry-run батча с ≥1 admit сам зовёт `validate_sources` с ненулевым exit — PR #26: опечатка в словарном поле видна сразу, а не следующим прогоном) + скилл `.claude/skills/directed-search/` — протокол воспроизводимых поисковых кампаний (сетка запросов термин×юрисдикция×язык, верификация издателя по метаданным, inject — единственная дверь). Протоколы живут в открытом стандарте `.claude/skills/<name>/SKILL.md` (`agent-skills-packaging`, PR #27) — читаются Claude Code/Agent SDK/Copilot и др. без правки кода; словарные/константные значения внутри скилла указывают на источник истины (`vocab_axes.yaml`, `schema.CANDIDATE_SUMMARY_MAX`), а не дублируют его инлайном — та же дисциплина, что и в схеме. **`CandidateRecord`:** архетип канала не хранится полем — выводится из грамматики `connector_id` (`manual` | `search:<кампания>` | id кодового коннектора; enum `ConnectorKind` остался в протоколе Connector/API inject), `native_summary` ≤600 знаков (жёсткий отказ), легаси-поля старых файлов поглощает `extra="allow"`; дамп: `title` первым, пустая строка между записями. **Конвенции decisions.yaml:** `id` первым / `action` последним (код к порядку безразличен), содержательный контент EN, `rationale` = ТОЛЬКО факторы релевантности (не пересказ summary); файл эфемерен (один заход триажа). **Отказ типизирован** (PR #48): опциональный `reject_kind: unacquirable` (enum `RejectionKind`; опущенный ключ = легаси-семантика «содержательно не подходит», дефолт в store не пишется) разводит терминальный отказ и «нужен, но недобываем» — второй уходит в отдельную секцию worksheet и в популяцию (c) recheck, а не закрывается навсегда по ошибке из-за того, что смену обстоятельств некому заметить. Третье действие `action: revive` возвращает такого кандидата в ждущие (снимает отказ и probe-поля) — ЯВНОЕ решение человека, невоскрешение отклонённых через dedup при этом не ослабляется. Имена `reject_kind` (ключ решения) vs `rejected_kind` (поле кандидата) расходятся намеренно: язык действия vs хранимое состояние, та же пара, что `action: reject` → `rejected_reason`. **Дефолты admit:** `authority` — из doc_type, `track` — из jurisdiction/issuer_type (явный ключ побеждает — кейс draft; эхо «по дефолту: …» в сводке; аннотация `hidden_fields`); дефолты материализуются в meta.yaml полными значениями — слой знаний ничего не теряет. **Четыре registry-коннектора (PR #36/#39/#42/#46) — ОДИН архетип, курсорная стратегия диктуется формой источника, не вкусом:** bulk-дамп → курсор = версия дампа + DuckDB-bronze (`discovery/registry_store.py`, единый слой архетипа, не только под AGORA); живой индекс → курсор = множество виденных нативных id (`diff_cursor`, DuckDB не участвует — кэшировать живой индекс незачем). `agora.py` (ETO AGORA/Zenodo) — bulk; `eurlex.py` (SPARQL/CELLAR), `aiforgood.py` (ITU AI Standards Exchange), `oecd.py` (OECD.AI Policy Navigator) — живые. Фильтр объёма у каждого свой (EuroVoc-концепты / категории / гибрид «всё не-US + узкая US-проба»), тюнится YAML-конфигом, не кодом. Durable-уроки, добытые этими четырьмя: (1) исключение платных каталогов и `draft`-записей — решение УРОВНЯ КОННЕКТОРА (структурная недобываемость, не низкая релевантность); оно же открыло трек `tech-standards`; (2) недокументированный backend требует **shape-гейта честной деградации** — изменившийся ответ обязан дать громкий отказ, а не тихие «0 кандидатов», плюс снапшот сырья как страховку; (3) **барьеры данных**: из объектов, живьём замеченных Faker.js-порчеными, читается только заведомо валидное поле (`.name`), PII-поля редакторов (`*Email`/`*ByName`) не читаются нигде; (4) кросс-слойно: `promote_candidate` принимает `language`-override — registry-каналы структурно не дают язык в метаданных реестра. **Пятый архетип — discovery-snowball реализован** (PR #43, 2026-07-24): backward-snowballing по СОБСТВЕННОМУ корпусу, не по внешнему реестру — `snowball.py` майнит уже допущенные документы (`raw.*`/`doc.md`) на ссылки на новые источники. Три канала всегда активны (PDF-аннотации, HTML `href`, напечатанные URL в doc.md); четвёртый — опциональная LLM-стадия текстовых цитат без URL (`--with-citations`/`emit.text_citations`): детект секций-цитат по заголовку (с fallback на плотные годовые блоки) + verbatim-гейт против галлюцинаций (заголовок цитаты должен буквально встречаться в тексте секции). Продакшн-модель — `minimax/minimax-m3`, фолбэк `google/gemini-3-flash-preview` на пустой/невалидный ответ примари (живой A/B трёх кандидатов; третий отклонён — reasoning-token exhaustion). Лиды без резолвнутого URL — отдельный файл `sources/.state/snowball_leads.yaml` (не слой кандидатов). CLI: `discover.py snowball [--doc/--track/--tier/--exclude-domain/--with-citations/--max-candidates]`; при `--with-citations` сам подгружает `.env` (PR #44 — `discover.py`, в отличие от `run_pipeline.py`, раньше этого не делал). Ложные срабатывания density-фолбэка на табличном контенте закрыты (`fb738bc`: строки markdown-таблиц разрывают run).

Модель bge-m3 (~543 МБ) качается отдельно в `pipeline/models/bge-m3-onnx-int8/` (int8 ONNX, команды — в проектном плане). Тесты, зависящие от модели, помечены `@pytest.mark.model` и в CI пропускаются (`-m "not model"`). Векторы разных моделей несравнимы — на корпусе живёт одна модель за раз.

Golden-самосверка (`test_convert_golden.py`, `@pytest.mark.corpus`): свежая конвертация каждого локального `raw.*` должна байт-в-байт совпасть с уже лежащим `doc.md` — эталон корпус сам себе (тела документов не в git).

Заменил старую word-gap-эвристику (см. историческую сноску ниже) на векторную геометрию: rects/curves/images страницы кластеризуются, три guard'а (мин. элементов, макс. доля страницы, макс. текста-на-элемент — «сомнение → проза») отсеивают декор/боксированную прозу от настоящих фигур; грид→таблица, одноосевая последовательность→список, растр — дедуп по content-хэшу (декор молча, `RASTER_DECOR_MIN_REPEATS=3` повторов по документу) + маркер крупных уникальных (`RASTER_MIN_PAGE_FRACTION=0.08` площади страницы, `> [Image, p. - **OCR** (`convert/converters.py::_ocr_normalize` + `convert/ocr_headings.py`, PR #14) — сканы без текст-слоя: `ocrmypdf --skip-text` (subprocess, системный apt, языки по `TESSERACT_LANGS` — `cnr/sr→srp_latn`, мультиязычный резерв ru/ar/zh/es/ja/de/fr/it, CJK/арабский без `+eng`-суффикса) кладёт невидимый текст-слой **IN-PLACE в `raw.pdf`** — один PDF-файл на документ, не отдельный сайдкар; `.state.yaml` пересчитывает sha256/размер/mtime АТОМАРНО с мутацией — ВНУТРИ `_ocr_normalize`, сразу после `staging.replace(raw)`, не в конце стадии `_do_convert` (PR #53, В1 — закрывает crash-окно: kill-9/OOM между мутацией и завершением стадии раньше оставляли sha скачанного оригинала при уже-мутированном raw, `needed_stages` планировал передобычу поверх выполненной OCR-работы; иначе следующий stat-guard принял бы мутацию текст-слоя за порчу файла); отдельно `original_sha256` (PR #28, spec ocr-eval-harness) захватывает хэш ДО этой мутации — единственный способ доказать соответствие издательскому оригиналу, пишется один раз в точке первой нормализации, для сканов, сконвертированных раньше этого поля, восстановим только пере-добычей. Передобыча с НОВЫМИ байтами сбрасывает поле в `None` (`_do_download`, PR #53, В2; PREMIS-практика «фиксити переустанавливается, не наследуется») — свежескачанный raw сам есть новый издательский оригинал, без сброса прежнее значение (хэш ПРЕЖНЕЙ редакции) вечно врало бы `--recheck-deep` ложным drift'ом на наших же байтах; байт-идентичная передобыча поле не трогает. Т.к. raw «вылечивается» от статуса скана навсегда, повторное распознавание «это OCR-документ» на будущих переконвертациях (`--force`/бамп версии конвертера) — по метаданным `ocrmypdf` (`Creator`-поле PDF, `_was_ocr_normalized()`), переживающим саму мутацию текст-слоя; `was_ocr_normalized()` (без подчёркивания, PR #53, В13) — публичный алиас для потребителей ВНЕ convert-слоя (`acquire/recheck.py`, `run_pipeline.py`, `ocr_eval.py`). `ocr_headings.py` — отдельный markdown→markdown пост-проход, precision-first, три тира по убыванию точности (ключевые слова ANNEX/CHAPTER/SECTION/Article + региональные ČLAN/CLAN/GLAVA/PRILOG/ODJELJAK/DIO → CAPS-фраза+тело → голая нумерация ≤2 уровней): штатная кластеризация `pdf_to_markdown.py` по размеру шрифта калибрована на чистых кеглях цифровых PDF и на OCR-bbox (геометрический шум OCR, не типографика) даёт ненадёжные/противоречивые уровни, поэтому на OCR-ветке она полностью ИГНОРИРУЕТСЯ — `ocr_headings` снимает любую её разметку и переоценивает строку заново сама (единый источник истины, не два несогласованных). Живой полевой тест (`me-crps-registration-law-2025`, ME, первый скан в корпусе) — известные системные ограничения, найденные им, задокументированы в самом спеке (`docs/pipeline/convert/tech_specs/convert-ocr/spec.md`, раздел «Известные ограничения после живого теста»); один класс (OCR-искажение текста — спутанные диакритика/цифры/римские числа) сознательно НЕ чинится — попытка угадывать/подправлять текст опаснее для юридического корпуса, чем косметическая неточность в заголовке.

санитизация деградирует `#`-заголовки ответа в bold (не переподчиняют дерево секций) и снимает mermaid-фенсы, не прошедшие реальный рендер (`chart_render.mermaid_renders`, публичная). **Witness-гейт фигур** (`figures_vlm.witness_defects`) сверяет VLM-описание с независимым свидетелем — подписями региона/группы, извлечёнными детерминированно ДО вызова модели — тем же принципом, что `convert/lint.py::witness_checks` для OCR. `run_pipeline.py`: стадия `figures` реконсилируется по `has_bare_markers` (ФС-based desired-state, как остальные стадии), флаги `--no-cloud`/`--vlm-model`. `ocr_headings.py` получил additive-режим для облачного вывода (не выбрасывает разметку, как для tesseract-ветки, а дополняет). Живой чекпоинт: `me-crps-registration-law-2025` (скан) + `me-undp-aila-2025` (UNDP AILA, cnr) — ноль галлюцинаций, числа сошлись.
- **OCR-эталон и A/B-харнесс** (`convert/ocr_eval.py` + шим `ocr_eval.py`, PR #28, spec ocr-eval-harness) — то же, чем `ab_eval.py` служит для retrieval, но для качества OCR: до этого спека правило «смену модели — только через локальный A/B» для OCR было формально в силе, но неисполнимо (не было ни эталона, ни автоматизированного сравнения). Два тира: **тир 1** — точность против вручную выверенного эталона (`tests/fixtures/local/ocr_gold/`, gitignored, тело документа корпуса — CER через собственный Левенштейн, recall диакритики, числовой инвариант, точность заголовков `(уровень, текст)`); **тир 2** — попарные расхождения кандидатов на ВСЁМ документе, эталона не требует (согласие моделей не доказывает правильность — коррелированные ошибки; но согласие ПРОТИВ эталона — сильный сигнал дефекта самого эталона, живой случай на приёмке). `run_document`/`run_pages`/`run_tesseract` работают ИСКЛЮЧИТЕЛЬНО через копию raw во временном `workdir` — `convert_scan` пишет кэш-сайдкары рядом с переданным путём, прогон по оригиналу затёр бы production-кэш документа. Кандидат `tesseract` — в наборе по умолчанию (текст-слой уже в raw, читается бесплатно, ~30 мс), даёт «пол» качества. Живой первый прогон (2026-07-22, me-crps) подтвердил production-модель `gemini-3-flash-preview`: кандидат-преемник `gemini-3.6-flash` систематически путает УРОВЕНЬ заголовков (5 вместо 3) при идентичном тексте — воспроизведено в обоих тирах независимо (детали и evidence — бэклог §14).
- **DOCX** (`convert-docx`, PR #20, 7 коммитов; резолюция chart-kind переведена на data-driven — `chart-data-extraction`, PR #30, 2026-07-22) — третий `SourceFormat`. `convert/docx_groups.py`: XML-препроцессор ДО mammoth — детектирует composite-группы фигур (`mc:Choice`▸`wpg:wgp`) и голые нативные чарты (`w:drawing`▸`c:chart` вне AlternateContent, данные в `embeddings/*.xlsx`) в `word/document.xml`, вырезает объект целиком, заменяет текстовым сентинелом (`id12 = sha256(XML-поддерево)[:12]`) — сентинел проходит текстовый путь как обычный текст и сохраняет ТОЧНУЮ позицию фигуры в потоке; captions собираются из поддерева (для группы) или `c:title` чарт-парта (для чарта) ДО вырезки — zero-loss даже без VLM. chartEx (sunburst и т.п.) сознательно НЕ детектируется отдельно — Word кладёт готовую fallback-PNG в `mc:Fallback`, её забирает штатный mammoth-путь. Текстовый путь — прямой `mammoth` (custom image-handler, кастомный `MarkdownConverter`-сабкласс `markdownify`, НЕ `markitdown` — версийный скос приватного API), фолбэк-листинг `word/media/*` с **orphan-фильтром** (маркер только для media, реально референсированных XML-частями — посторонние файлы в архиве не всплывают даже маркером, privacy по построению). **Резолюция расщеплена по kind** (было: обе через VLM): kind="group" (composite/SmartArt, genuinely dataless) — БЕЗ ИЗМЕНЕНИЙ, `figures_vlm.py` (сузившаяся до group-only грамматика маркера `docx group`) и рендерер `_render_docx_group`: изолированный мини-docx → `soffice --headless` → PDF → кроп по bbox → JPEG → VLM-вызов и кэш `.figures.yaml`, требует системный LibreOffice, деградирует до маркера+captions при отсутствии/отказе. kind="chart" (нативный `c:chart`, data-backed) — `chart_data.parse_chart`→`chart_render.render_chart` (см. XLSX-бюллет ниже, container-agnostic ядро), резолвится `docx_groups.inject_group_markers` В МОМЕНТ конвертации, БЕЗ soffice/сети; пустое извлечение (нет numCache) → тот же caption-фолбэк маркер, что раньше. Живой стресс-тест group-пути (8 разнотипных объектов) — ноль фабрикаций в VLM-выводах.
- **XLSX** (`convert-xlsx`, PR #22) — четвёртый `SourceFormat`. Безпотоковая (cell-anchored) модель: у `.xlsx` нет линейного потока прозы, документ — сетка листов/ячеек. `converters.py::_convert_xlsx` — многолистовая GFM-таблица на лист (`openpyxl`, НЕ `calamine` — нужен доступ к merged-cell структуре и chart-XML-частям), слитые ячейки схлопываются в якорную, скрытые листы включаются с маркером `(hidden)` (честность важнее приватности), формулы — только закэшированное `data_only=True`-значение. `convert/xlsx_charts.py` — детект встроенных чартов (`xl/charts/*.xml` через `xdr:from`-якорь, `iter_chart_entries` — единый обход под метаданные И roots), `id12` по XML-структуре чарта.
- **Нативные OOXML-чарты (xlsx+docx) — data-driven, БЕЗ render+VLM** (`chart-data-extraction`, PR #30, 2026-07-22, заменил прежний render+VLM путь целиком — ~1500 строк удалено, включая `xlsx_charts.extract_chart_workbook`/mutual-ownership-систему). `convert/chart_data.py::parse_chart(chart_root)` — container-agnostic чистая функция (схема `c:chart` идентична в `xl/charts/*.xml` и `word/charts/*.xml`): читает ТОЛЬКО закэшированные `<c:numCache>`/`<c:strCache>` (+ `strLit`/`numLit` литералы, scatter через `xVal`/`yVal`) → `ChartData` (тип/title/оси/formatCode/категории/серии). `convert/chart_render.py::render_chart(data)` — GFM-таблица ВСЕГДА + mermaid для типов с объективным mermaid-конструктом (`pie`/`doughnut`→`pie`, `column`/`bar`/`line`/`area`/`combo`→`xychart-beta`, `radar`→`radar-beta`; scatter/stacked-бары/прочее — конструкта в mermaid нет вовсе, таблица-only). **Финальный гейт перед выдачей — реальный рендер через `mermaidx`** (`mermaid_renders`, публичная с PR #52 — переиспользуется и `figures_vlm`-санитизацией VLM-ответа выше, runtime-зависимость `requirements.txt`, embedded QuickJS, без Node/браузера): любой отказ реального mermaid.js → откат к таблице (структурные эвристики ловят рискованную ФОРМУ, но не гарантируют, что рендерер примет результат — живой баг: кавычки в `pie title` синтаксически валидны, но рендерятся буквально, синтакс-валидаторы это пропускали). xlsx: `_convert_xlsx` добавляет провенанс-строку `sheet {sheet}, anchor {anchor}` (детерминированный порядок по `xdr:from`; английский литерал — PR #52, машинный контракт `doc.md` одноязычен). docx: позиция точна by construction (сентинел в потоке), резолюция — в `docx_groups.inject_group_markers` (kind="chart"); kind="group"/SmartArt остаётся на VLM (см. DOCX-бюллет). Пустое извлечение (нет numCache) → честный caption-фолбэк, как раньше. Тестовая фикстура — World Bank GovTech Maturity Index Dataset, хирургически обрезана (`govtech-2025-charts.xlsx`, gitignored `tests/fixtures/local/`, регенерируется трекаемым `tests/fixtures/make_govtech_charts_fixture.py`; CC BY 4.0, 9 листов/55 чартов, все достижимы byte-identical — обрезаны только избыточные строки/колонки листов, не сами чарты) — финальная приёмка: 0 крашей, 0 отказов рендера, детерминизм подтверждён.

## `pipeline/scripts/convert/pdf_to_markdown.py` — как устроен и его реальные ограничения
Полностью автоматический конвертер PDF→Markdown на `pdfplumber` (MIT, pure Python, CPU-only, ~70MB venv — сознательно НЕ marker-pdf/datalab-to, см. ниже почему). Механизмы:
- **Восстановление порядка чтения в многоколоночной вёрстке** — geometric gap-анализ по bounding-box словам (`detect_columns`: проекция покрытия по x, поиск устойчивого по высоте разрыва в центральной зоне страницы), а не regex-эвристика поверх готового текста.
- **Иерархия заголовков** — по кластерам font-size конкретного документа (пересчитывается заново для каждого PDF из его собственной гистограммы), НЕ по regex на нумерации "1.1.1" — работает и для документов без явной нумерации разделов. Только цифровой PDF-путь — на OCR-ветке эта кластеризация ненадёжна (шум bbox, не типографика) и полностью игнорируется в пользу отдельного `ocr_headings.py` (см. «Слой конвертации» выше).
- **Колонтитулы/номера страниц** — частотный анализ ЦЕЛЫХ строк (не отдельных слов) в верхней/нижней полосе страницы.
- **Сноски** — отдельный (заниженный, ~65% от размера тела) порог только для крошечных надстрочных номеров-маркеров — сам текст сноски обычно почти неотличим по размеру от текста обычных врезок/кейс-стади, попытка развести их одним порогом теряла бы кейс-стади.
- **Таблицы** — `pdfplumber.find_tables()` + фильтр по АБСОЛЮТНОМУ числу непустых ячеек (не по доле — у настоящих таблиц со слитыми ячейками доля заполненности так же низка, как у шумных обломков диаграмм).
- **Диаграммы/инфографика** — векторная геометрия через `pdf_graphics.py` (PR #12, детали — «Слой конвертации» выше); прежняя word-gap-эвристика по тексту заменена полностью (её слабости — см. абзац «Известное ограничение» ниже).

**Известное ограничение — пороги изначально калибровались на одном документе** (Сингапур, IMDA Model AI Governance Framework for Agentic AI v1.5) и не переносятся вслепую на следующие страны: 2-й прогон (Эстония, эстонский, 47 стр.) сразу выявил два класса дефектов — оба с тех пор закрыты структурно (векторная геометрия `pdf_graphics.py` вместо word-gap-эвристики, `merge_split_tables`/`_drop_empty_columns` для многостраничных таблиц), диакритика õ/ä/ö/ü извлекалась чисто. Урок durable: каждый НОВЫЙ конвертер-путь проверяется живым документом, а не переносом порогов. Актуальная конкретика порогов:
- `MIN_GAP_PT=14.0`, `COLUMN_ZONE=(0.30, 0.70)`, `MIN_GAP_HEIGHT_FRAC=0.45` (детектор колонок) и `TINY_MARKER_RATIO=0.65` (сноски) — абсолютные числа, не относительные к кеглю конкретного документа
- Детектор колонок ловит только ОДИН разрыв (максимум 2 колонки) — 3-колоночная вёрстка не поддержана
- Заголовки различаются в основном по РАЗМЕРУ шрифта; документ с одинаковым кеглем заголовка/тела закрывает bold-фолбэк A1 (`convert-hardening`, 2026-07-19) — строка целиком bold, кегля не мельче тела, короткая, без хвостовой пунктуации промоутится в заголовок НИЖЕ всех размерных уровней; заголовки без ЛЮБОГО типографского выделения (ни размером, ни насыщенностью) остаются слепым пятном (цифровой путь; для OCR-пути см. `ocr_headings.py` — тоже своя, отдельно задокументированная граница возможностей)
- **Специфический риск для CJK-документов (Япония и т.п.)**: `pdfplumber.extract_words()` токенизирует по пробелам — если исходный PDF на языке без пробелов между словами (японский и другие CJK), группировка в строки/колонки может не сработать; проверить наличие англоязычной версии до прогона. Пока не проявлялось живьём — в корпусе нет CJK-документов (проверено rg по `meta.yaml`).

**Практика на каждый новый документ:** тот же выборочный аудит, что делался для Сингапура — сверка списка заголовков, проверка таблиц на дубли/фрагментацию, чтение хотя бы одного «сложного» (многоколоночного/с диаграммой) участка целиком. Не доверять результату вслепую.

## Почему НЕ marker-pdf / НЕ Jina Reader (сравнение проведено 2026-07-15)
- **marker-pdf** (datalab-to) — GPL код + Open RAIL-M веса, тянет ~1.3GB+ CUDA-стека (torch/cudnn/nccl) даже на CPU-only задаче. На рабочей машине физически несовместим: GeForce 940MX (Maxwell, compute capability 5.2) выпала из поддержки CUDA 13.x/актуального PyTorch — установку пришлось прервать и полностью вычистить.
- **Jina Reader** (r.jina.ai) — по умолчанию PDF.js (не LLM), но при живом тесте на реальном гос. PDF (тот же сингапурский документ) получил 403 Forbidden — WAF издателя (tech.gov.sg) заблокировал IP Jina, хотя прямой `curl` с той же машины скачал файл без проблем. Системный риск, специфичный именно для корпуса государственных документов — у многих гос. сайтов WAF банит дата-центровые/прокси IP.
- `pdfplumber` — ноль GPU-зависимостей, работает локально, не проксирует запросы через сторонние серверы (важно, т.к. документы могут быть чувствительны к раннему разглашению до публикации итогового пакета предложений).

## Известные факты о рабочей машине
Linux Mint 22.3 Cinnamon, ноутбук 2015 года (Intel Core i5-6200U, 2 ядра/4 потока), 8GB RAM, дискретная GPU (GeForce 940MX, Maxwell) НЕСОВМЕСТИМА с современным CUDA/PyTorch — см. предупреждение выше про marker-pdf. Интернет — LTE-роутер, ~1MB/s, сельская местность. Перед предложением любых GPU-зависимых ML-инструментов — сначала проверять CPU-fallback реалистичность или явно предупреждать перед многогигабайтной загрузкой.

**(Ре-)эмбеддинг корпуса — облачный по умолчанию (PR #16, 2026-07-18): минуты, не часы.** Живой замер на смок-приёмке: полный корпус (4 док, 628 чанков ≈ 322k ткн) — ~1–1.5 мин на модель (gemini-001@1024, LTE). Целевые 1000 док ≈ 80M ткн, wall-clock — часы СЕТИ, не CPU (машина свободна; экстраполяция по замеру ~322k ткн/мин ≈ 4–5 ч последовательно). Обрыв любой природы (сеть/kill/OOM/закрытие VS Code) теряет ≤64 чанка — чекпоинтинг `embed_and_store`, рестарт добирает инкрементально (проверено kill-9-тестом). ⚠ OpenRouter-кредиты: перед батч-наполнением сверять баланс с прогнозом расхода (актуальные прогнозы/замеры — во внутренних записях). При ЛОКАЛЬНОМ фолбэке (`--embed-backend bge`) прежние правила в силе: длительность определяется ЧИСЛОМ ЧАНКОВ и давлением на 8GB RAM (живой инцидент PR #15: свободно ~200 МБ, своп 1.7–3.5 ГБ — прогон кратно дольше ориентира) — перед оценкой проверять `free -h`/`vmstat`.

**Политика: бюджет и стоимость работы пайплайна — не для показа наружу.** Денежные суммы, тарифы, балансы и оценки расходов НЕ попадают ни в какие коммитящиеся артефакты: трекаемые файлы (включая этот), сообщения коммитов, тела PR, docstrings/комментарии кода. Их место — только внутренние, gitignored записи: memory ассистента и `docs/` (спеки/бэклог).

**Фоновые процессы не гарантированно переживают закрытие VS Code/терминала — даже будучи POSIX-detached.** Эмпирически подтверждено (PR #15): длинный фоновый прогон (`vector_store.py embed-corpus`/`ab_eval.py`), запущенный через harness `run_in_background`, жил в СОБСТВЕННОЙ POSIX-сессии (свой `SID`, без управляющего терминала — проверено `ps`/`/proc`), тем не менее был убит при закрытии/перезапуске VS Code (дважды, потеряно ~30-40 минут вычислений каждый раз). Точный механизм не установлен — НЕ `systemd-logind` (`KillUserProcesses=no`, залогиненная сессия не завершалась) — вероятно cgroup-очистка терминала VS Code. **Не полагаться** на выживание длинных фоновых задач при закрытии хост-приложений. Для эмбеддинга риск ЗАКРЫТ чекпоинтингом (PR #16: `embed_and_store` батчами — смерть процесса любой природы теряет ≤64 чанка, рестарт добирает; бэклог §11); systemd user-service остаётся деплой-заметкой, не обязательным механизмом. Для ДРУГИХ будущих длинных фоновых задач принцип тот же: сначала чекпоинтинг, потом способ демонизации.
