# G2AI_ME — Claude Code memory

## Memory-keeping principle

Covers the whole memory system: this file (CLAUDE.md, always loaded), the assistant's external memory (`~/.claude/projects/.../memory/` — MEMORY.md + `project_*`/`feedback_*`/`reference_*`), and internal design docs (`docs/`, same discipline pinned separately for the `pipeline_improvements.md` backlog). One principle, every level.

**Stale entries are REPLACED, not appended to.** Nth implementation of an already-described pattern → consolidate (one description + what's new this time), don't add a twin paragraph. A structural fix closing a recurring problem → compress prior-incident history to outcome+fix, don't leave it in full beside the fix. Size after an edit holds or shrinks, never grows monotonically per merge.

**First compression/deletion candidate: curator-motive mentions detached from architectural fact** ("curator asked", "user decision"). The curator remembers their own motives; they don't affect the build — only what got built and how it works matters. Who/why initiated a change is procedural noise, not architecture. Exception: when the motive IS the rule (e.g. a live confidentiality policy, not its adoption history) — phrase as a rule ("X isn't done"), not a decision act.

**Nuance for external memory:** decision rationale in `feedback_*`/`project_*` (**Why** lines, rejected alternatives) is exempt — it explains non-obvious constraints useful at future forks, and `feedback_*` bodies are untouchable under `/memory-sync`. "Curator asked for X" (who/when, noise) vs "X rejected because Y" (architectural reason, kept).

## About the project
Independent research track, two parallel linked lines:

1. **G2AI corpus** (`sources/`, `pipeline/scripts/`) — collects and structures international state practice on GenAI/agentic-service policy, infra, regulation ("state as an MCP server"), focused on small states but not only. Goal: a proposal package from an independent expert/industry body, incl. a draft Montenegro AI Strategy to 2030 while the government drafts its own.
2. **Broader Montenegro digital-sovereignty vision** (`docs/project_core/vision_and_plan.md`, v03) — parallel, not nested in G2AI: a `cnr` locale core, mobile keyboards, Wikipedia/Wikidata grounding, B2B2G with telecoms, long-run goal a state–frontier-lab partnership ("Icelandic path"). G2AI corpus is one input, not the only one, not the bulk of that doc.

Both lines share one concern: accurate, complete representation of Montenegro in the digital/AI space.

Closes the class "a main() test with no `--db` silently wiped the prod index every run, CI never caught it".

## Document-intake pipeline
1. **Discovery + triage (pre-acquisition)** — a binary admission gate: a doc is in the corpus or not, no mid-tier (an error is fixed by deleting the record, not downgrading a label). WebSearch: confirm the real document/publisher/date, assess relevance — ⚠ a title from someone else's list/search is NOT proof it exists (live UAE/Estonia fictitious-title cases). NOT WebFetch for the body — runs through a small model, not verbatim; fine for metadata only. Candidate-layer mechanics, the sole door `discover.py inject` (dedup+provenance by construction; a new EDITION reuses it with `--supersedes <doc-id>`), the batch session `worksheet`→decisions.yaml→`apply` — under "Knowledge layer" below; search campaigns — skill `.claude/skills/directed-search/`. **Strictness is channel-differentiated** (policy, not code — spec `triage-channel-policy`): `manual` with a document the curator personally read — no WebSearch, one touch (`inject`→`promote(rationale from reading)`→pipeline, no return visit); `directed_search`/`registry` (batch) — WebSearch mandatory, candidates inherit its unreliability.
2. **Downloading the original** — via `run_pipeline.py`: ladder `direct → official_alt → (browser, expected=html only) → manual → archive` on a WAF block/dead URL (see "Knowledge layer"), into `sources/{track}/{entity}/{doc-id}/raw.*` (ext = record's `SourceFormat`); sha256/channel → `.state.yaml`.
3. **Conversion** — `converters.resolve_converter(raw)` dispatches by extension → `doc.md`; frontmatter is generated from `meta.yaml` (`schema.render_frontmatter`), never hand-written. Details — "Convert layer" below.
4. **Life post-intake** — `run_pipeline.py --recheck` (time loop): a periodic curator command checking, via conditional requests, whether the official URL is alive and the file unswapped; findings (`drift`/`link-rot`/`resurrected`) flag in `.state.yaml`, decision is the human's. Details — "Time loop" bullet below.

## Knowledge layer: metadata, graph, semantic search
Over the assembled `.md` — a layer for cross-doc analysis (Phases 1-4 done, merged via PR #1; plan/status — `docs/pipeline/knowledge/tech_specs/knowledge-graph-metadata/spec.md`, gitignored). CPU-only, embedded, no servers/JVM/CUDA. Run FROM ROOT: `.venv/bin/python pipeline/scripts/<script>.py`.

- **Metadata** — `schema.py` (slimmed, corpus-layout-v2): curated core `SourceRecord` (~21 fields) in `meta.yaml` — id, `entity_id`/`track`, issuer_type, geo_scope, language (ISO 639-1, or 639-3 where absent — Montenegrin `cnr`), dates, doc_type, authority, source_url, sensitivity, rights, topics, g2ai_pattern, summary, relations, admission (Dublin Core + minimal analytics). Operational data (sha256/acquisition/…) is a separate `OperationalState` in a `.state.yaml` sidecar (machine-written via `save_state`/`fsio.atomic_write_text`, never into `meta.yaml`); `raw_size`/`raw_mtime_ns` is a stat guard vs. full re-reads. **No manual freshness bookkeeping in the core** (`in_force`/`dates.last_checked` dropped, `post-acquisition-lifecycle`): a manual "in force?" bool and "last checked" date rot across hundreds of records by construction — replaced by the machine-written `acquisition_checked` (recheck cursor) and DERIVED validity from `supersedes`/`superseded_by` edges (`schema.superseded_ids()`, normalizes both directions). ⚠ `meta.yaml` is the only tracked file under `sources/`, so such slims need a DATA migration same-commit: `extra="forbid"` else breaks `validate_sources` on a fresh clone (same for `.state.yaml`/`OperationalState`, but that file is local — the migration is a one-off script the curator runs on their own corpus, not committed; e.g. dropping dead `translation_status`, `acquire-convert-seam-hardening`). `external_disclosure_allowed(sensitivity)` is the single predicate for "confidential isn't disclosed to third parties", replacing 8 scattered `Sensitivity.confidential` comparisons across 7 modules; an AST guard test blocks regrowth. Layout invariants (folder==id, entity_id, track; global id uniqueness) — one `schema.check_layout()`, used by `load_records()` (raise) and `validate_sources.py` (collect); raw/doc.md/state paths are DERIVED from the folder. `render_frontmatter()` builds frontmatter. `validate_sources.py` validates structure+vocab+id uniqueness+relations+`admission`+folder invariants+(`geo_scope=national`⇒`entity_id`==iso2), returns `(errors, records)` — consumers reuse records without re-walking the tree; non-zero exit on error, gated in CI too.
- **Vocabularies** — `pipeline/vocab/vocab_*.yaml` (grow organically); `g2ai_pattern` = a transferable pattern (cross-country axis), `topics` = subject. `jurisdictions.yaml` (EU/ASEAN) gives `member_of` edges. `axes` (`vocab_axes.yaml`) — triage's analytical axes (`agentic_g2ai`/`digital_sovereignty`), growing RARELY (unlike organic topics/g2ai_pattern — a new axis means new methodology): `Admission.axis` moved from a hardcoded `Axis` enum into this vocab, gated by `validate_sources.py`. Rule: an enum if code branches on the value OR it's an ordered scale; a vocab for nominal classification.
- **Graph** — `build_graph.py`: a heterogeneous NetworkX graph (document/pattern/topic/issuer/jurisdiction nodes; exemplifies/about/published_by/applies_to/member_of edges + document→document from relations). GraphML export. Queries: `docs_by_pattern`, `docs_in_bloc`, `lineage`. **Derived projection: full rebuild every run, the auto-layer NEVER writes into the curated core, distinguishable by construction** (`layer` on EVERY edge: `L0` curated / `L1` deterministic auto-layer / `L2` reserved for future LLM extraction — 3-valued from day 1, no later migration).
- **Temporal validity (graph-v2 Phase A)** — DERIVED from edges, no field bookkeeping: `validity_intervals()` — pure fn of the registry (`valid_from = dates.effective ?? published`; `supersedes`/`superseded_by` normalize to one direction, close the predecessor's interval at the successor's start; `amends` does NOT close — an amendment changes, doesn't replace; multiple successors → earliest + WARNING on successor count; a successor earlier than its predecessor → WARNING for an empty interval — else a doc silently vanishes from ALL slices). Same argument that killed `in_force`. **Honest uncertainty**: `validity_known=False` when there's no own date OR an undatable successor — `as_of(graph, date)` ALWAYS includes such docs, flagged. Slice bounds: `valid_from` inclusive, `valid_to` exclusive. CLI `build_graph.py --as-of YYYY-MM-DD` (with `--graphml` exports the SLICE). Dates in GraphML as ISO strings, `""` for unknown.
- **L1: deterministic citation layer** (`graph/cite_mining.py`) — legal text is anomalously well cited FORMALLY; `cites` edges need ZERO LLM. **Both stages, extraction+resolution, are two-channel: machine + curated.** EXTRACTION: a regex registry, `_CONVERTERS`-pattern (`celex`/`eu_act`/`eu_act_slash`/`sluzbeni_list_cg`/`iso`/`nist`/`eli_uri` — a new id is an ENTRY, not a core edit; `IDENTIFIER_PREFIXES` = the sole prefix-space def) + the reference's `aliases` (text→canonical id; literal + word boundaries, case-insensitive, no regex generalization). Aliases exist because a doc legitimately cites an act BY NAME with no number: 6 "EU AI Act" mentions in `oxford-insights-gairi-2025` gave the corpus its first real L1 edge. ⚠ alias precision is the curator's: bare "AI Act" could mean Korean/Taiwanese/Australian/US acts too (4 false edges) — use a distinguishing form; unbounded list growth is an L2 trigger, not a reason to generalize matching. RESOLUTION id→doc-id: auto from `source_url` + `identifiers` (curated beats heuristic; a stale entry → warning+report, not a crash). The URL channel is deliberately WIDER than prose: `CELEX:`/`CELEX%3A` reads the id verbatim (any sector/letters/length, consolidation/corrigendum tails) — the prefix removes ambiguity entirely, future eurlex admissions self-resolve. Symmetric — `data.europa.eu/eli/`/`eur-lex.europa.eu/eli/`: `eli/{reg|dir|dec}/{year}/{number}`→sector-3 CELEX is deterministic; host is MANDATORY in the anchor (national ELI portals like `eli.gov.pl` share the path grammar — no host would forge false CELEX). Prose regexes hold the v1 boundary (sector 3 + LRDE + 4 digits) — extending them is forbidden: a false edge costs more than a missed one. Unresolved goes to `sources/.state/cite_leads.yaml` as discovery RAW MATERIAL (door stays `inject`). No cache: deterministic, cheap (246ms/1.1MB). ⚠ **Patterns are calibrated on LIVE text** — first run gave 0 citations at 242 live refs (converted text has no compact CELEX at all): number order depends on era (`YEAR/no.` since 2015, `No no./YEAR` before), the old year can be 2-digit — both traps yield a WRONG link, not an empty one. The `1950–2049` year gate drops a match if a number sits where a year should. A golden (`tests/fixtures/cite_golden.yaml`, 128 ids, a fixed doc PAIR, marker `corpus`→`heavy`) guards precision — the pair is fixed on purpose so a whole-corpus golden isn't rewritten every new doc.
- **Expansion primitives** (`graph/expand.py`) — a contract for the future `analyze-evidence`: `expand(doc_ids, hops)` — exact typed neighborhood over document→document edges ONLY (never via concept nodes: every doc has a topic+publisher, "via topic" degenerates to half the corpus); `personalized_rank()` — PPR over the whole graph, concept nodes as connective tissue. `Neighbor.links` carries ALL parallel edges of a pair (both `supersedes` L0 and `cites` L1 can legitimately link one pair); `etypes` gates the TRAVERSAL, not just output. ⚠ PPR is a CUSTOM power iteration, not `nx.pagerank` (needs scipy in networkx 3.x, absent here; the private `_pagerank_python` is the same risk class as the `markitdown` version skew). Measured (1000 docs): 201ms at `PPR_TOL=1e-4`; 1e-9 gave 458ms with an IDENTICAL top-20.
- **Search** — one `pipeline/index/corpus.db` (SQLite): `corpus_index.py` (canonical ~512-token chunks + FTS5 `unicode61`), `vector_store.py` (vectors + brute-force cosine; `embed-corpus`/`vsearch`/`models`/`drop-model` — the last two for A/B-namespace hygiene: `gc_vectors` cleans only its own model's orphans, `models` lists all namespaces, `drop-model <name>` removes one). Chunks are canonical, shared FTS+vectors. **2-level incrementality:** a doc is the FTS-reindex unit (`doc_state(doc_id, fingerprint)`: only a changed `doc.md` re-chunks/re-indexes via external-content `'delete'`/`'insert'`; `--force`/a `chunk_max_tokens` change → a reference full rebuild; the increment is one transaction); a chunk is the embed unit, keyed by **`content_hash`** (sha256 of `breadcrumb+text`, not the ephemeral `chunk_id`): only new hashes embed + `gc_vectors` clears orphans, a shared boilerplate chunk = one vector for all carriers. "A vector points at someone else's text" is eliminated BY CONSTRUCTION → the old stop-gap (`DROP vectors`/`vectors_fingerprint`/`VectorsStaleError`) is gone, replaced by an honest missing-report in vsearch. `index_meta` holds `corpus_fingerprint` (a stat-based global "is there work" gate), `chunk_max_tokens`, `schema_version` (currently v4 — PR #55 dropped `target_fit`/`assessed_stage`; opening an old-version DB recreates derived tables). `search` escapes the query by default (`sanitize_fts_query` — a hyphen breaks FTS5 bareword grammar), `--raw` for honest syntax. **The brute-force ceiling (measured, `e2c3976`):** `load_vectors` streams the whole model matrix into a pre-allocated buffer (peak ~1x matrix size). At ~163k target chunks (1000 docs): ~640MiB, ~2.8s/query — fits 8GB RAM, latency is the constraint. Revisit at ~100k chunks or when delay hurts; float32→float16/int8 needs no re-embed (a local BLOB conversion), so no rush.
- **Retrieval facade (`analyze-retrieval`)** — `chunk_text()` sections by markdown heading BEFORE packing: every chunk gets a `breadcrumb` (ancestor-heading chain, `"H1 › H2"`), never crossing a section boundary; `embed_input(breadcrumb, text)` is what the embedder actually sees. 2-column FTS (`text`, `breadcrumb`) + `doc_facets`/`topics_map` tables (schema v3; filled from curated records, rewritten in full per index run — cheaper than diffing); `corpus_fingerprint` is meta-aware (`doc.md`/`meta.yaml` stats), and since PR #52 STATE-aware too (+`.state.yaml`) — an axis/topic edit OR a recheck/lint finding, no text change, refreshes facets but NOT re-chunk/re-embed. **Convert↔knowledge seam provenance** (additive columns, no `SCHEMA_VERSION` bump): `chunks.reconstruction`/`chunks.markup_heavy` — a chunk carries a VLM figure reconstruction (bounds from the terminated block in `core/markers.py`) or is mostly markup; `doc_facets.fidelity`/`ocr_model`/`quality_flags` — acquire/convert signals, previously read by NO consumer. All ANNOTATION on `ScoredChunk`/`hsearch` (`⚠ reconstruction`/`⚑ <flag>`), no filtering — trust policy is a future `analyze-evidence` call. Single entry point — `analyze/retrieve.py::retrieve()`: RRF merge (`RRF_K=60`/`POOL=50`, constants not config) of FTS5+vector with facet filters; `embedder=None` = an honest FTS-only degrade. **The `superseded` facet** — an additive `doc_facets` column via the shared `_ensure_column(conn, table, column, ddl)`, its calls listed in `_ensure_facet_columns` (a new one = one line, not a copied fn; generalized across tables once `chunks` became a target too). `RetrievalFilters.include_superseded` defaults False: a superseded law edition in top-k is a silent error of the "wrong text" class. Two non-obvious spots, both regression-tested: `retrieve(filters=None)` NORMALIZES to `RetrievalFilters()` (the commonest call path, where a dataclass default wouldn't fire); the gate is SET SUBTRACTION, not facet-SQL (else `allowed=None` = "whole corpus" would collapse to a concrete set and zero results on an unfilled-facets DB). Side effect: while no `supersedes` edges exist — a full no-op, inclusion arrives by itself. CLI `hsearch.py` — a thin facade (`--backend bge|openrouter|none`, `--include-superseded`, `--sources` with an advisory `corpus_fingerprint` staleness warning on stderr). The gate is public as `analyze.retrieve.apply_superseded_gate` — `ab_eval.py` computes it ONCE/run, applies to ALL 3 modes (else with the first real `supersedes` edge the modes would silently compare different document universes). `ab_eval.py` — `--mode fts|vector|hybrid|all`; control queries in tracked `pipeline/config/eval_queries.yaml`. **Empirical (not a defect):** FTS gives ~0% hit@k on paraphrases (an implicit AND over a full sentence rarely matches prose) — why the hybrid exists; cross-lingual EN→cnr via vectors is confirmed on `me-crps-registration-law-2025`.
- **Embeddings — API-first** (spec `embed-api-first`) — `embed.py`: production path `OpenRouterEmbedder` (`DEFAULT_BACKEND="openrouter"`, `DEFAULT_CLOUD_MODEL="google/gemini-embedding-001"`, an MRL slice to `DEFAULT_CLOUD_DIMS=1024` ON THE CLIENT; namespace suffix `@1024`; `"dimensions"` is NOT sent — a fixed-dim provider REJECTS it, live nemotron fact). `embed()` fails fast on fewer dims than `dims` (else `@1024` could silently lie); `max_tokens` from `CLOUD_MODEL_TOKEN_LIMITS` by model name. Model chosen by live A/B (user+Fable 5): hit@10=100% en/cnr/et, fixing bge's et weakness (60%→100%); qwen3-8b (MMTEB favorite) and nemotron:free both failed — **never trust published benchmarks without a local A/B (2nd confirmed case after EmbeddingGemma)**. Armor: retry/backoff `RETRY_SCHEDULE` (429/5xx/network/error-in-a-200-body via `_InbandError`, ≤5 tries; other 4xx fail fast); `embed_and_store` checkpoints in batches of 64 (any failure loses ≤1 batch, restart catches up — kill-9 tested); a sensitivity gate `chunk_hashes(exclude_all_carriers_in=confidential_doc_ids)` skips cloud-embedding a chunk whose EVERY carrier is confidential (local backend has no filter); the gate covers ALL 3 cloud-embed doors (`vector_store embed-corpus`, `run_pipeline --embed`, `ab_eval`); backend distinguished via `isinstance(embedder, OpenRouterEmbedder)`, not a string (`ab_eval` compares a heterogeneous embedder list); `doc_facets.sensitivity` — additive, no schema bump. Local FALLBACK — `OnnxBgeEmbedder` (bge-m3 int8; offline/confidential, not the main path). `ab_eval.py` — `--backends bge|openrouter:<model>` + per-language slices (en/cnr/et). Chunking tokenizer stays `bge_tokenizer.py` regardless of embedder; `.env` (`OPENROUTER_API_KEY`) — `env.py`.
- **Orchestrator** — `run_pipeline.py`: idempotent end-to-end over `sources/` (download→convert→frontmatter→index). Desired-state reconciliation (work derives from the FS) — a repeat run is a no-op, self-healing; index rebuild reconciles the same way via `corpus_fingerprint` (a global gate, not an in-run flag), reindexing itself is incremental over `doc_state`/`content_hash`. `--embed` reconciles vectors on an FTS rebuild (`--embed-backend {openrouter,bge}`, cloud default; a cloud failure after retries doesn't break the already-committed FTS part); standalone catch-up — `vector_store.py embed-corpus`. The summary prints a vectorless-chunk count with a catch-up hint, and a local-OCR-path scan count (cloud failure=WARNING vs. deliberate confidential=INFO), unconditionally, incl. `--dry-run`. Manual/untracked raw (`--no-download`) is adopted — sha256 fixed by the reconciliation step; the same step resets the stat-guard triple on a matching sha with only-stat drift (backup/restore/touch) — else `needed_stages` would recompute a full sha256 every planning pass forever. Atomic artifact writes go through `fsio.py`; `fsio.exclusive_flock` on `schema.corpus_lock_path()` = `sources/.state/corpus_mutation.lock` mutually excludes ALL corpus mutators — the normal stage run, `--recheck`, AND mutating `discover.py` subcommands (`inject`/`apply`/`discover`/`snowball` outside `--dry-run`; a live audit repro once showed physical shard loss when the lock covered only the first pair); a concurrent run gets `AlreadyLocked`/exit 1. `needed_stages` checks "`raw.*` ext == curated `source_format`" — a mismatch gives a loud per-doc failure, never a silent by-file conversion. Backoff is symmetric for download+convert (`convert_failed` trio, `convert_deferred`) — same `RETRY_BACKOFF_DAYS`; a pathological doc (e.g. hours-long OCR timeout) doesn't repeat its cost every run. A doc failure never breaks the batch; a quality gate, `--dry-run`/`--force`/`--only`/`--no-download`/`--embed`/`--watch-dir`; `--recheck` is a separate mode INSTEAD OF the stages (time loop below). Deliberately no Airflow/Prefect/Dagster (server-based, overkill for this scale).
- **Acquisition / WAF resilience** — `acquisition.py` (spec `source-acquisition-ladder`): ladder `direct → official_alt → browser → manual → archive` at download (`browser` — `expected=html` only, below). **Block detection is 2-channel, grows by one rule** (3 live vendors: Cloudflare, F5/Akamai, AWS WAF): BODY signatures (`CHALLENGE_BODY_MARKERS`) + HEADER fingerprints (`_has_waf_header_fingerprint`: `cf-ray`/`__cf_bm`, `x-amzn-waf-action`=challenge/captcha). Neither HTTP code nor size suffices: a 42,936-byte F5 stub passes as valid HTML, an AWS challenge arrives as `202 Accepted` with an EMPTY body. The inverse rule is just as strict: the detector is the header's VALUE, not its presence (`Server: BigIP` alone false-positives on real govt content). Curl network failures (DNS/connect, exit 6/7) classify as `dead`→archive, never crash the doc. A DIAGNOSIS error isn't cosmetic — the reason string lands in `.state.yaml`, read as a verdict; a non-challenge miss adds "server returned HTML expecting {format}" (mirroring the reverse `_classify_html` diagnosis). `manual` is 1-click (`xdg-open` + a downloads watch-folder), sync only under `--only`; candidates are title-matched (a rough word threshold) — a stray PDF can't quietly become the original; `--watch-dir` disables the check. `archive` is a Wayback CDX snapshot for confirmed-dead URLs (`fidelity: archived_snapshot`, never `live`; `confidential` disables archive; takes the GENUINELY freshest snapshot via `limit=-N`). Acquisition state (`acquisition_method`/`fidelity`/`acquisition_checked`/`retrieved_snapshot_date`+sha256) writes to `.state.yaml`. **A success also closes the time loop** (below): bootstraps `etag`/`http_last_modified` from ALREADY-PARSED headers (zero new requests), gated to `VALIDATOR_CAPTURE_RUNGS = {direct, official_alt}` (archive/browser/manual headers would be junk validators); requests Wayback SavePageNow (`_SNAPSHOT_FIDELITIES = {live}`; `rendered` excluded — a datacenter Wayback crawler would hit the same WAF the browser rung was needed for, so the insurance is declared inapplicable, not faked); clears backoff and `recheck_finding`. ANY ladder failure is caught by one handler into `acquisition_failed`/`acquisition_failure_reason` (naming types would forget one — `ManualAcquisitionTimeout` once slipped through); `needed_stages` backs off downloads `RETRY_BACKOFF_DAYS = 7` days (only `--force`/`--only <id>` break through). **The `browser` rung** sits between `official_alt` and `manual`, `expected=html` only: one attempt via `core/browser_resolver.py` (Puppeteer-core drives Lightpanda over CDP) before `manual` — the watch-folder stays PDF-only otherwise. Vendor map — memory `project_headless_browser_resolver`. A resolver failure (`BrowserResolverUnavailable`) silently degrades to old behavior. Tooling — `pipeline/browser/` (manifest tracked, binary gitignored); `Fidelity.rendered` marks a JS render. PDF/DOCX/XLSX and `dead` aren't touched by the resolver at all. **Format axis is a registry, not if/elif** (`acquisition._FORMAT_PROFILES`, mirrors `convert._CONVERTERS`): one entry per `SourceFormat`.
- **The time loop (recheck)** — `acquire/recheck.py` (spec `post-acquisition-lifecycle`): without it the corpus is a SNAPSHOT — intake happens once, nobody checks URL liveness or a file swap. A separate mode, exclusive with the stages: `run_pipeline.py --recheck [--recheck-limit N] [--recheck-deep]` — a curator command, not a daemon. **Invariant mirroring "projection never writes the core": automation NEVER mutates `meta.yaml`/`raw.*`** — only operational artifacts; substantive decisions use existing doors (`inject --supersedes` / `--force --only`). Mechanics — **a conditional GET, never HEAD**: a block shows only in the body, HEAD returns none — a `200` challenge would be indistinguishable from content. `classify_recheck()` is pure "state+response→desired state": 304/match→`etag_confirms`++; a validator change→`drift` (html only past `HTML_STABLE_CONFIRMS=2` — govt-portal validators are volatile); 404/exit 6,7→`link-rot`; a WAF→"unverifiable", not a finding; `fidelity=archived_snapshot` inverts semantics (dead=expected, alive=`resurrected`). A clean outcome NEVER clears a standing finding — only re-acquisition does. `acquisition_checked` bumps on ANY outcome, else a stuck-finding doc sits first in rotation forever. Three populations: (a) records with raw (superseded excluded via `superseded_ids`; `confidential` NOT excluded — no third party in a conditional request), (b) unacquired — "opened up yet?", success only CLEARS backoff, (c) `rejected_kind: unacquirable` candidates, FORMAT-AGNOSTIC (`classify_probe` — no `source_format` yet). Publishers vary in validators (Last-Modified only / ETag only / none) — the last gets a defensive "nothing to compare" branch, not a false drift. **Discovery seam hardened** (memory `project_discovery_acquire_seam_hardening`): population-(b)'s rotation cursor (`acquisition_probe_checked`, bumps on EVERY probe) is separate from the backoff anchor (`acquisition_failed`+`acquisition_failure_reason`, one event); population (c) reconciles via the SOLE impl `manual.unacquirable_candidates()`; `--recheck --dry-run` prints the plan with no network/lock/write; `--recheck --only` skips population (c) entirely, its probe caps at `fetch_raw(byte_cap=65536)` (a Range request, `206`=alive), populations (a)/(b) get no cap.
- **Relevance triage / candidate layer** — `schema.py`+`validate_sources.py` (spec `source-relevance-triage`): a gate FILTER before acquisition. Candidates live in a **separate layer, `sources/candidates/`**, as `CandidateRecord` (light `extra="allow"`, carries acquisition provenance; NOT `status:candidate` on `SourceRecord`); admission is a type conversion, `promote_candidate() → SourceRecord`. One-shot and BINARY — metadata+WebSearch before acquisition, an `Admission` verdict (`axis`+`rationale`) on 2 axes (`agentic_g2ai` narrow / `digital_sovereignty` broad); no mid-tier — an error is fixed by deletion. Date is a signal not a gate: `frontier_year` in `pipeline/config/triage.yaml`. Acquisition provenance is NOT copied to `meta.yaml`. An auto gate-judge is planned (`project-auto-triage-acquisition-plan`), not specced; triage is manual for now. **The candidate generator (DISCOVERY)** — charter `docs/pipeline/discovery/charters/architecture.md` (archetypes: registry/outlet_watcher/directed_search/manual/snowball). **The core** (`discovery-core`): `discovery/` — the `Connector` protocol, a `_CONVERTERS`-style registry, an orchestrator with failure isolation + idempotent reconciliation. **A connector is a PURE FUNCTION OF THE SOURCE**: the core neither gives nor takes state; a connector always returns its full current view, filtering the known is `dedup`'s sole job; `status` (`no_new`/`fetched`) is computed ONCE by the orchestrator from the dedup outcome. Cursors don't exist as a concept: they saved fractions of a second, and "a repeat run is a no-op" is held by `dedup` alone. ⚠ The harm wasn't cost: marking `seen_ids` across the ENTIRE output (incl. dedup-absorbed, never-stored items) permanently masked candidates — removing it returned 44 documents and populated 3 fields, inert across the whole queue until then. Where a cursor genuinely gated work, a **RAW-DATA cache** (`pipeline/discovery_cache/`) stands instead: it suppresses repeat WORK and returns a result, a cursor suppressed OUTPUT. Acquisition is cached, mapping NEVER is — a `map_link` fix reaches the whole queue on a warm cache, no version bump; snowball's invalidation key is (`document_fingerprint`, enabled `emit` channels), agora's is `bronze_has_version`. **The store** — a shard per `connector_id`: `save` partitions the WHOLE list, writes only changed bytes (mutating a foreign shard is automatically correct, no dirty tracking); an emptied shard is deleted. **Dedup** is cross-connector, no fuzzy libs (determinism over recall): dict indexes in ONE pass (O(M+N)), 3 STRATEGIES with strict priority over a single pool. (1) URL identity `_identity_url` — normalized `source_url`, but **an unreliable value isn't a key**: `url_provenance: suspect` returns `None`. (2) `issuer`+`normalized_title`+`doc_date`. (3) `_source_identity` = (`connector_id`, `native_id or raw_hash`, `supersedes`) — source identity, ⚠ ONLY for a keyless candidate, NOT a fallback for the first two missing (a reliable-URL candidate matching nothing IS a new doc). Key is `native_id`, not `raw_hash` (a description digest, changes on any edit). Rejected candidates aren't re-injected. `dedup()` returns `DedupOutcome` (fresh/absorbed/absorptions); an absorption keeps the displaced address in `alternate_source_urls`; `inject` takes the real absorber from `absorptions`. **A merge follows the source RELATIONSHIP, not a field list** (`candidate-identity-hardening`): one's own source updates what it produced, a foreign source fills only empties, `_MERGE_EXEMPT` is untouchable either way (guarded by AST gate `test_dedup_exempt_matches_unproduced_fields`). ⚠ Known defect (backlog §33): a same-source merge also overwrites KEY fields (`source_url`/`title`/`native_id`), migrating the absorber's identity. **`admitted_as`** (a doc-id) is stamped by `apply_decisions` only after `meta.yaml` is written, the SOLE reconciliation key for both queues; checked against the registry, not trusted — deleting the doc folder returns the candidate to the queue by itself. The pair (URL identity, edition) is a key ONLY for dedup: `CandidateRecord.supersedes` enters every key AND `raw_hash`; `inject --supersedes <doc-id>` is the new-edition door; `promote_candidate` materializes the `supersedes` edge (consumed by graph-v2 validity). **Manual/directed channels**: `inject` (a typed factory via dedup, idempotent, rejects don't resurrect), `worksheet` (a pending table, RECONCILED, no stored status), `apply` (batch promote/reject by `raw_hash`, per-decision isolation, `--dry-run`; a non-dry-run batch with ≥1 admit self-calls `validate_sources`) + skill `.claude/skills/directed-search/` (a reproducible search-campaign protocol). Protocols live in the open `.claude/skills/<name>/SKILL.md` standard; vocab/constant values in a skill point at the source of truth, never duplicate it. **`CandidateRecord`:** channel archetype isn't stored — derived from `connector_id`'s grammar; `native_summary` ≤600 chars (a hard rejection); legacy fields absorbed via `extra="allow"`. **A DECISION IS THE CURATED PART OF THE RECORD**: `promote_candidate(cand, curated: dict)` instead of 20 named params. `curated` overlays candidate knowledge, so any `SourceRecord` field is expressible with no code line — incl. `dates` (76% of the queue has empty `doc_date`). A key typo is a LOUD rejection (`extra="forbid"`). Control keys — `schema.CONTROL_DECISION_KEYS` (never in `curated`). **decisions.yaml conventions:** `id` first / `action` last, content in English, `rationale` = relevance factors ONLY; the file is ephemeral. **Rejection is typed:** `reject_kind: unacquirable` (omitted=irrelevant) separates a terminal reject from "needed, unacquirable" — the latter feeds a worksheet section + recheck population (c); `action: revive` returns it to pending. **Admit defaults:** `authority` from doc_type, `track` from jurisdiction/issuer_type, `source_format` from `native_format_hint` (eurlex sets html by construction, others via `dedup.format_hint_from_url()`); an explicit key wins, the summary echoes the default. **Provenance instead of default trust** (`triage-intake-hardening`): an unreliable field is flagged (`title_provenance: derived` — 52% for snowball; `url_provenance: suspect`), and MUST get an explicit admit-decision key — one impl `_missing_conditional_fields` also feeds the worksheet's `missing` column. `official_alt_url` is an optional admit key, not a `CandidateRecord` field. **Four registry connectors are ONE archetype**, differing only in source shape+volume filter: `agora.py` (ETO AGORA/Zenodo, bulk via DuckDB bronze), `eurlex.py`/`aiforgood.py`/`oecd.py` (live indexes). Lessons: excluding paid/`draft` records is a CONNECTOR-level call (structural unacquirability, opened the `tech-standards` track); an undocumented backend needs a **shape gate** (a changed response fails loudly, no silent "0 candidates") + a raw snapshot; **data barriers** against Faker.js/PII — read only `.name`, never `*Email`/`*ByName`; ⚠ non-obvious corruption (a working foreign `website`) is caught by `ambiguous_websites`, tagged `url_provenance: suspect`, not dropped; a foreign response's line order isn't guaranteed — aggregation needs `sorted`. Politeness is config-driven: `crawl_delay_seconds` from robots.txt where present. **The 5th archetype — snowball**: backward-mines its OWN corpus for links. Three channels always on (PDF annotations, HTML `href`, printed doc.md URLs); a 4th is an optional LLM stage for text citations (`--with-citations`): detects citation sections by heading (falls back to dense year blocks) + a verbatim gate against hallucination. ⚠ **The 3 URL channels carry no real title** — the anchor is a positional artifact, 52% unusable, flagged `title_provenance: derived`; fixing with a heuristic is forbidden. Production model `minimax/minimax-m3`, fallback `google/gemini-3-flash-preview`. Leads with no resolved URL — `sources/.state/snowball_leads.yaml`. Run width is set by DOCUMENTS, not a findings cap: `discover.py snowball [--doc/--track/--exclude-domain/--with-citations]`.

The bge-m3 model (~543MB) downloads separately into `pipeline/models/bge-m3-onnx-int8/`. Model-dependent tests are `@pytest.mark.model`, skipped in CI. Vectors of different models aren't comparable — one model per corpus at a time.

## Convert layer: format registry, graphics, HTML, OCR, cloud VLM tier, DOCX
A multi-format `raw.* → doc.md` layer (charter `docs/pipeline/convert/charters/architecture.md`; all specs implemented). The orchestrator (`_do_convert`) knows no formats — `converters.resolve_converter(raw)` dispatches by extension.

- **Registry** (`convert/converters.py`) — `_CONVERTERS: dict[str, Converter]` (keyed by extension), `Converter(name, version, convert)`; a `version` bump triggers auto-reconversion (`needed_stages` checks against `.state.yaml`). Typed failures: `UnsupportedFormat`, `NeedsOCR` (a cheap `_detect_scan` pass, `SCAN_MIN_TEXTPAGE_FRACTION=0.5`), `ConversionError`. A golden self-check (`test_convert_golden.py`, `@corpus`): reconverting every local `raw.*` must byte-match the existing `doc.md`.
- **Graphics/infographics** (`convert/pdf_graphics.py`) — digital-PDF path only. Replaced the old word-gap heuristic with vector geometry: rects/curves/images cluster, 3 guards (min. elements, max. page share, max. text-per-element — "in doubt→prose") filter decor from real figures; grid→table, a single-axis sequence→list, raster dedup by content hash (decor silently, `RASTER_DECOR_MIN_REPEATS=3`) + a marker for unique large ones (`RASTER_MIN_PAGE_FRACTION=0.08`, `> [Image, p. N — raster content not analyzed]`). Bbox-anchored insertion (fixed tables/images drifting to the doc's end). `pdf` converter → v2.
- **HTML** (`convert/converters.py::_convert_html`+`convert/eli.py`) — `trafilatura==2.1.0` (`favor_recall=True`). `SourceFormat` in `SourceRecord` drives `raw.*` extension, the `classify_response(expected=)` branch, `find_wayback_snapshot(mimetype=)`. `eli.py` promotes ELI markup (EUR-Lex: `CHAPTER`/`SECTION`/`Article`/`ANNEX` id-prefixed `<div>`s) to real `<hN>` before `trafilatura`, wraps `<body>` in `<article>` (else trafilatura LOSES every heading picking "main content" — confirmed by tracing; general risk for any doc with no explicit `<article>`).
- **OCR** (`convert/converters.py::_ocr_normalize`+`convert/ocr_headings.py`) — text-layer-less scans: `ocrmypdf --skip-text` (via `TESSERACT_LANGS`, `cnr/sr→srp_latn`) writes an invisible layer **IN PLACE into `raw.pdf`**; `.state.yaml` recomputes sha256/size/mtime ATOMICALLY with the mutation — INSIDE `_ocr_normalize`, not at `_do_convert`'s end (else a kill-9/OOM mid-mutation leaves a stale sha, planning re-acquisition over done OCR work). `original_sha256` (spec `ocr-eval-harness`) captures the pre-mutation hash — the only proof of a published-original match; written once, unrecoverable for pre-existing scans except by re-acquisition. Re-acquisition with NEW bytes resets it to `None` (PREMIS: fixity resets, doesn't inherit) — else the PREVIOUS edition's hash would forever lie to `--recheck-deep`; a byte-identical re-fetch leaves it. Re-detecting "OCR document" on future reconversions reads `ocrmypdf`'s PDF `Creator` metadata (survives the mutation); `was_ocr_normalized()` lives in `core/pdfmeta.py` (removed 2 layer inversions where acquire/discovery read convert directly). `ocr_headings.py` is a separate precision-first post-pass, 3 tiers (keywords ANNEX/CHAPTER/SECTION/Article + regional ČLAN/CLAN/GLAVA/PRILOG/ODJELJAK/DIO → ALL-CAPS phrase+body → bare numbering ≤2 levels): normal font-size clustering is unreliable on OCR bbox noise, so it's fully IGNORED on the OCR branch. A live field test (`me-crps-registration-law-2025`, the corpus's 1st scan) found known limits, documented in the spec; OCR text distortion (confused diacritics/digits/Roman numerals) is deliberately NOT fixed — guessing text is riskier than a cosmetic inaccuracy for a legal corpus.
- **Hardening + the good-enough freeze** (`convert-hardening`) — a bold-heading fallback (`_bold_heading_level`): equal heading/body font size isn't fatal — a fully-bold, no-smaller, short, no-trailing-punctuation line promotes to a heading below every size-based level. Multi-page tables fragmented with repeated headers/empty columns are fixed by `merge_split_tables` (merges only adjacent blocks with an IDENTICAL header) + `_drop_empty_columns`. `convert/html_preprocess.py` is a first-match Strategy registry of HTML preprocessors (a new legal portal = one line, no `_convert_html` edit) + a heading-loss guard. `convert/lint.py` gives auto-QA (`no-headings`/`text-loss: <ratio>`/`table-ragged: <n>`) into `.state.yaml`, never blocking conversion. **Good-enough policy:** calibration is FROZEN — edit only on (a) an analytical-use-blocking defect, (b) ≥3 similar defects, (c) a new format; the alternative is targeted cloud escalation (below). A full audit runs only for a NEW converter path's first doc; after that, lint flags + a spot check.
- **The cloud VLM tier** (`convert-cloud-tier`) — targeted escalation on the trigger above. `core/openrouter.py` is a shared chat client (`RETRY_SCHEDULE`, `InbandError`, same armor as `embed.py`). `convert/cloud_ocr.py` does per-page VLM OCR of scans (batches by `OCR_BATCH_PAGES=20`/`OCR_BATCH_MAX_MB=8`, a cache sidecar, `DEFAULT_VLM_MODEL="google/gemini-3-flash-preview"` — winner of a live A/B on OCR AND figures); wired as an alternative to tesseract. `convert/lint.py::witness_checks` compares cloud output to a witness (local tesseract) by token recall + a numeric invariant — a divergence goes to `lint_defects`, never blocks (the worst VLM error class is a silent digit swap); the defect line lists the actual divergent numbers (capped 10/side). `convert/figures_vlm.py` gives VLM figure semantics: scan doc.md for markers → render the region → VLM → cache `.figures.yaml`. **Injection is a BOUNDED block** (a marker + sanitized answer + a `> [/VLM interpretation …]` terminator, grammar in `core/markers.py`); sanitization demotes `#` headings to bold and strips mermaid fences failing a real render. A figures witness gate checks a VLM description against independently-extracted captions. `run_pipeline.py`: the `figures` stage reconciles on `has_bare_markers`, flags `--no-cloud`/`--vlm-model`. Live checkpoint: `me-crps-registration-law-2025` (scan) + `me-undp-aila-2025` (cnr) — zero hallucinations, numbers matched.
- **The OCR reference and A/B harness** (`convert/ocr_eval.py`, spec ocr-eval-harness) — what `ab_eval.py` is for retrieval, but for OCR quality: before this, "swap only via a local A/B" was unenforceable — no reference, no automated compare. Tier 1: accuracy vs. a manually verified reference (`tests/fixtures/local/ocr_gold/`, gitignored — CER via custom Levenshtein, diacritic recall, a numeric invariant, heading accuracy). Tier 2: pairwise divergence over the WHOLE doc, no reference needed (model agreement doesn't prove correctness — correlated errors; but agreement AGAINST the reference flags a flawed reference). `run_document`/`run_pages`/`run_tesseract` work only via a temp `workdir` copy (a run on the original would overwrite production cache). `tesseract` is the default candidate (free, ~30ms), a quality floor. First live run confirmed `gemini-3-flash-preview` over `gemini-3.6-flash`, which systematically confuses heading LEVEL (5 vs 3) on identical text (backlog §14).
- **DOCX** (`convert-docx`; chart-kind resolution moved to data-driven) — the 3rd `SourceFormat`. `convert/docx_groups.py` is an XML preprocessor before mammoth — detects composite figure groups (`mc:Choice`▸`wpg:wgp`) and bare native charts (`w:drawing`▸`c:chart`) in `word/document.xml`, excises the object, replaces it with a text sentinel (`id12 = sha256(XML subtree)[:12]`) keeping its exact stream position; captions are collected before excision — zero loss even without a VLM. chartEx (sunburst etc.) isn't detected separately — Word's own `mc:Fallback` PNG is picked up by mammoth. The text path is direct `mammoth` (a custom `markdownify` subclass, NOT `markitdown` — a private-API version skew), a `word/media/*` fallback listing with an **orphan filter** (only media actually referenced by XML parts — privacy by construction). **Resolution splits by kind** (both used to go through VLM): kind="group" (composite/SmartArt) — unchanged, `figures_vlm.py`+`_render_docx_group`: an isolated mini-docx → `soffice --headless` → PDF → crop → JPEG → a VLM call, needs LibreOffice, degrades to marker+captions on failure. kind="chart" (native, data-backed) — `chart_data.parse_chart`→`chart_render.render_chart` (below), resolved at conversion time with NO soffice/network. A live stress test (8 object types) — zero fabrications.
- **XLSX** (`convert-xlsx`) — the 4th `SourceFormat`. A streamless (cell-anchored) model — `.xlsx` has no linear prose flow. `_convert_xlsx` gives a multi-sheet GFM table (`openpyxl`, not `calamine` — needs merged-cell structure and chart parts), merged cells collapse to the anchor, hidden sheets get a `(hidden)` marker, formulas use only the cached `data_only=True` value. `convert/xlsx_charts.py` detects embedded charts (`xl/charts/*.xml`), `id12` from XML structure.
- **Native OOXML charts (xlsx+docx) — data-driven, NO render+VLM** (`chart-data-extraction`, replaced the old path entirely, ~1500 lines removed). `convert/chart_data.py::parse_chart(chart_root)` is a container-agnostic pure function (the `c:chart` schema is identical in both formats): reads ONLY cached `<c:numCache>`/`<c:strCache>` (+ literals, scatter via `xVal`/`yVal`) → `ChartData`. `convert/chart_render.py::render_chart(data)` gives a GFM table ALWAYS + mermaid for types with an objective construct (`pie`/`doughnut`→`pie`, `column`/`bar`/`line`/`area`/`combo`→`xychart-beta`, `radar`→`radar-beta`; scatter/stacked have no construct — table-only). **The final gate is a real render via `mermaidx`** (`mermaid_renders`, public, embedded QuickJS, no Node/browser needed): any real-mermaid.js failure falls back to the table (a live bug: quoted `pie title` text is syntactically valid but renders literally — syntax validators missed it). xlsx adds a provenance line `sheet {sheet}, anchor {anchor}`. docx position is exact by construction; resolution is in `docx_groups.inject_group_markers`. An empty extraction (no numCache) → an honest caption fallback. Test fixture — the World Bank GovTech Maturity Index Dataset, surgically trimmed (`govtech-2025-charts.xlsx`, gitignored, regenerated by a tracked script; CC BY 4.0, 9 sheets/55 charts, all byte-identical) — 0 crashes, 0 render failures, determinism confirmed.

## `pipeline/scripts/convert/pdf_to_markdown.py` — design and real limits
A fully automatic PDF→Markdown converter on `pdfplumber` (MIT, CPU-only, ~70MB venv — deliberately not marker-pdf/datalab-to, see why below):
- **Multi-column reading order** — a geometric gap analysis over bounding-box words (`detect_columns`: an x-coverage projection finding a height-stable central-zone gap), not a regex heuristic over finished text.
- **Heading hierarchy** — by font-size clusters of the specific document (its own histogram each time), not regex on "1.1.1" numbering — works with no explicit numbering too. Digital path only — unreliable on OCR bbox noise, fully ignored there in favor of `ocr_headings.py`.
- **Headers/footers/page numbers** — a frequency analysis of WHOLE lines in the page's top/bottom strip.
- **Footnotes** — a lowered (~65% of body) threshold for tiny superscript marker numbers only — footnote text itself is nearly the same size as ordinary callouts, so one threshold would lose case studies.
- **Tables** — `find_tables()` + a filter on the ABSOLUTE non-empty-cell count (not a ratio — real merged-cell tables and noisy chart fragments share a low fill ratio).
- **Charts/infographics** — vector geometry via `pdf_graphics.py` (above); the old text word-gap heuristic is fully replaced (weaknesses below).

**Known limit — thresholds were calibrated on one document** (Singapore, IMDA v1.5) and don't transfer blindly: run 2 (Estonia, 47pp) found 2 defect classes, both fixed structurally since (vector geometry, `merge_split_tables`); õ/ä/ö/ü extracted cleanly. Lesson: every NEW converter path needs a live-document check, not carried-over thresholds. Current specifics:
- `MIN_GAP_PT=14.0`, `COLUMN_ZONE=(0.30, 0.70)`, `MIN_GAP_HEIGHT_FRAC=0.45` (columns), `TINY_MARKER_RATIO=0.65` (footnotes) — absolute, not font-relative
- The column detector catches only ONE gap (max 2 columns) — 3-column layouts unsupported
- Headings differ mainly by SIZE; equal-size docs use the bold fallback above. Headings with NO typographic marker at all remain blind (digital path; OCR has its own limit, `ocr_headings.py`)
- **CJK risk (Japan etc.):** `extract_words()` tokenizes on whitespace — a spaceless-word-language PDF may break line/column grouping; check for an English version first. Not seen live — no CJK docs yet.

**Practice per new document:** the same spot audit as Singapore — check the heading list, tables for dupes/fragmentation, read one "hard" (multi-column/chart) passage in full. Don't trust results blindly.

## Why NOT marker-pdf / NOT Jina Reader (compared 2026-07-15)
- **marker-pdf** (datalab-to) — GPL + Open RAIL-M, pulls ~1.3GB+ CUDA (torch/cudnn/nccl) even CPU-only. Physically incompatible here: GeForce 940MX (Maxwell, cc 5.2) dropped from CUDA 13.x/current PyTorch — the install was aborted and cleaned up.
- **Jina Reader** (r.jina.ai) — PDF.js by default, but a live test on a real govt PDF got 403: the publisher's WAF (tech.gov.sg) blocked Jina's IP while a direct `curl` worked fine. A systemic risk for a govt-document corpus — many WAFs ban datacenter/proxy IPs.
- `pdfplumber` — zero GPU deps, local, no third-party proxying (matters given pre-publication sensitivity).

**Policy: pipeline budget/cost stays out of sight.** Amounts, tariffs, balances, cost estimates never enter a committed artifact: tracked files, commit messages, PR bodies, comments. Only internal gitignored records: the assistant's memory and `docs/`.

**Background processes may not survive closing VS Code/the terminal, even POSIX-detached.** Confirmed twice: a long run (`embed-corpus`/`ab_eval.py`) lived in its own POSIX session (own SID, no controlling terminal) and was still killed on VS Code close/restart. Mechanism unconfirmed — not `systemd-logind` (session stayed logged in), likely VS Code terminal cgroup cleanup. **Don't rely** on survival past a host-app close. Embedding risk is CLOSED by checkpointing (≤64-chunk loss, incremental catch-up); a systemd user-service remains a deploy note, not required. Same principle for other long tasks: checkpoint first, daemonize second.
